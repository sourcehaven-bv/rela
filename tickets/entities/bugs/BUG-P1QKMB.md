id: 'BUG-P1QKMB'
type: 'bug'
title: 'ensurePoolFloor re-encodes the whole DSN query, turning `options=-c search_path=x` into the unusable parameter name "+search_path"'
description: 'internal/jobs/pgqueue.go''s ensurePoolFloor added pool_max_conns by setting it on a url.Values and assigning u.RawQuery = q.Encode(). Encode rewrites every other parameter into Go''s encoding, and Go encodes a space as "+". A URI query reads "+" as a literal plus, not a space. An operator DSN carrying `options=-c%20search_path%3Dtenant` therefore came back out as `options=-c+search_path=tenant`, and the server rejected the parameter name "+search_path" with SQLSTATE 42704 (unrecognized configuration parameter). A correct, connectable DSN was turned into an unconnectable one by a helper whose only job was to size a connection pool. search_path is rela''s entire tenant-isolation mechanism, so the affected DSN is the normal production shape, not an exotic one. The defect was latent until pgx v5.11.0, which stopped decoding "+" as a space in URI query values to match libpq; before that pgx silently undid the corruption. Four schema-pinning test helpers built their DSNs the same way and failed the same way (12 tests) when the pgx bump landed in PR #1589.'
priority: 'high'
why1: 'ensurePoolFloor re-encoded the entire query string in order to set one parameter, so every unrelated parameter was rewritten into Go''s url.Values encoding.'
why2: 'Go encodes a space as "+" in a query value. A URI query reads "+" as a literal plus, so `-c search_path=x` became `-c+search_path=x` and the server parsed the parameter name as "+search_path".'
why3: 'url.Values.Encode was treated as a round-trip: parse, modify, re-encode. It is not. It is lossy for any value whose original encoding differs from the one Go prefers.'
why4: 'pgx before v5.11.0 decoded "+" back to a space, so the corrupted DSN still connected and neither a test nor a deployment ever surfaced it. The defect was masked by a downstream leniency rather than absent.'
why5: 'The tests asserted through url.Query(), which also decodes "+" back to a space, so they agreed with themselves no matter what was written to the wire. Nothing in the suite observed the DSN the way the server does, so an encoding invariant was checked with the same decoder that produced the encoding.'
prevention: 'ensurePoolFloor now rewrites only its own pool_max_conns pair and leaves every other parameter byte-for-byte (replaceRawParam); a non-URL key/value DSN is returned untouched. The regression tests assert through pgconn.ParseConfig and pgxpool.ParseConfig rather than url.Query(), so they see what the server sees, and they were confirmed to fail on the old implementation. The four schema-pinning test helpers now build key/value DSNs ("host=... dbname=... search_path=..."), the form the production helpers in internal/tenant, internal/docscapture and internal/appbuild already used and which has no escaping to get wrong. Generalizable lesson: never assert an encoding invariant with the same decoder that produced it, and treat parse/modify/re-encode of a foreign string as lossy unless the format guarantees a canonical form.'
status: 'done'
