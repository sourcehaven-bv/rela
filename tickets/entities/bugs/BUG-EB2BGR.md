id: 'BUG-EB2BGR'
type: 'bug'
title: 'Screenshot capture has no retry, so a single cold-start timeout fails the whole docs build'
description: 'internal/docscapture had no retry around a capture: one transient failure failed the screenshot{} island, and with it the E2E job. Two distinct symptoms, one cause. (1) `manual:479: lua: context deadline exceeded` — the 30s perCaptureTimeout expiring on the FIRST capture. (2) `manual:478: resolve: screenshot(list ""): could not dial "ws://127.0.0.1:35025/devtools/browser/...": context deadline exceeded` — Chrome failing to start. Both landed on the first screenshot{} of a 16-screenshot manual and none on the other fifteen, which is the signature of cold start rather than of a figure that cannot be taken: the docs build runs on the same runner as the full Playwright suite and immediately after it, so the first capture stands up a temp project, starts a server, launches Chrome and loads the SPA on a machine still under load. newBrowser also had no bound of its own — it inherited the docs build''s root context, which is a signal context with NO deadline, so the only limit was chromedp''s internal dial timeout, and the --no-sandbox fallback then paid that wait a second time. Measured across the last 60 CI runs: only 4 failed at all, but 2 of those 4 were this flake, making it the largest single cause of CI failure in the repo. One of the two dequeued a PR from the MERGE QUEUE (run 35181768822), so it blocked a merge rather than just a PR check.'
priority: 'high'
why1: 'A screenshot{} island ran its capture exactly once, so any transient failure failed the island and the build.'
why2: 'The transient failures are concentrated at cold start: the docs build shares a runner with the Playwright suite and runs straight after it, so the first capture pays project stand-up, server start, Chrome launch and the first SPA load at once, on a loaded machine.'
why3: 'newBrowser had no timeout of its own. It inherited a signal context with no deadline, so a slow launch was bounded only by chromedp''s internal dial timeout and the no-sandbox fallback repeated that wait.'
why4: 'The capture layer had no retry, but fixing only that was not enough and the first attempt at this fix still failed CI identically. internal/docs wired the Lua runtime with a hardcoded 30s buildTimeout as the PER-ISLAND cap, so gopher-lua''s SetContext aborted a screenshot island at 30s regardless of the 5-minute screenshotBuildTimeout the same function had just chosen for the build. The island was killed before Capture could return an error worth retrying, which made the retry unreachable code.'
why5: 'One operation was bounded in two places that did not know about each other, and the tighter bound was the one that did not scale with the work. The build correctly widened its ceiling for a screenshot build, then passed the un-widened constant down to the runtime three lines later, so the wider ceiling was never reachable. The resulting error read `manual:479: lua: context deadline exceeded`, attributing a ceiling defect to the manual''s line 479, which is why it looked like a flaky figure for so long rather than a wiring bug.'
prevention: 'Two fixes, because there were two defects. (1) internal/docs/runtime.go now passes the build''s TIER deadline to rlua.WithTimeout instead of the bare buildTimeout, so a screenshot island gets the screenshot ceiling. The build-wide child context still caps the TOTAL, so widening the per-island cap does not let N islands escape - pinned by TestScreenshotIslands_TotalStillBounded. (2) docscapture retries a capture up to captureAttempts (3), relaunching the browser between attempts, with retryability carried by typed sentinels (errPageLoadFailed, errRegionTooTall, errUnknownRole) so a genuinely broken figure still fails on the FIRST attempt with the same message. The classifier is a DENY list because transient failures are open-ended. newBrowser bounds each launch with a TIMER rather than context.WithTimeout: the first chromedp.Run allocates the tab and chromedp binds the tab lifetime to that context, so a child context cancels the browser on return and every later action fails with ''context canceled''. All three are mutation-tested - reverting the island cap reproduces the exact CI error, captureAttempts=1 fails the transient cases, bypassing the classifier fails the deterministic case, and removing the browser reset reproduces the context-canceled bug. Generalizable lesson: when one operation is bounded at two layers, the inner bound must be derived from the outer one rather than restated as a constant, or the outer widening is silently dead - and verify a reliability fix against the real pipeline, because this one passed every local test while still failing CI for a reason one layer up.'
status: 'done'
