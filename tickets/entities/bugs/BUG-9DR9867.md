## Description

A browser test of a multi-tenant server found these problems.

- A suspended or archived workspace answered 403 `unknown_tenant`, and the SPA
  showed a toast saying the tenant was unknown.
- An ended session showed a network error and a "Retry" that could not work.
- Error screens before the config loaded used the browser's language, so an
  English workspace showed "Opnieuw proberen".
- A refusal by the same-origin check showed "Request failed (403)".
- A read-only workspace still showed create buttons, and said nothing about
  being read-only until a write failed.

## Acceptance Criteria

- [x] A suspended workspace answers 403 `tenant_suspended`, an archived one 403 `tenant_archived`; the status route answers `suspended` or `archived`.
- [x] The SPA shows a full page for a suspended, archived or unknown workspace, worded with "workspace", in English and Dutch.
- [x] A 401, or a request the edge redirected to sign-in, shows "Sign in again" over the page, using the `login_url` the edge sends.
- [x] A 401 from a server that cannot identify anyone shows the server's explanation, not "Sign in again".
- [x] Screens shown before the config loads use `app.language`.
- [x] A same-origin refusal shows a clear message.
- [x] A read-only workspace shows a banner and hides its create buttons.
- [x] The behaviour is documented.
