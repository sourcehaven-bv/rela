## Symptom

On production, a single user editing an entity body inline sometimes gets
"Someone else changed the same lines of the body", with nobody else on the
system.

## Cause

The live `entity:changed` echo of the user's own save starts a view reload. A
second save starts after the reload is sent and is answered before it. When the
reload lands, `landView` calls `recordServerSnapshot` and resets the body's base
and token to the older body. The next save sends the old token, gets 412, and
the three-way merge (base v1, ours v3, theirs v2 = our own save) conflicts.

Code: `EntityDetail.vue` `onEntityChanged` (guard checks only pending edits),
`landView`; `useAutoSave.ts` `recordServerSnapshot`. Reproduced by
`EntityDetail.bodyConflict.test.ts` against the fake API; the reverse order
passes.

## Fix

1. Considered and dropped: letting `useAutoSave` treat a 412 whose current token is one of its own as no conflict. Tokens hash the value, so another user's revert to an earlier value would be overwritten silently (review RR-BCOTPJH). A 412 always merges or reports a conflict.
2. `useEntitySession`: one per entity on screen, owning reads and writes. A read lands only if its session is current, no newer read landed, and no write completed while it was on its way; otherwise it reads again. Live events mark the session stale and reload once when no write is pending. `EntityDetail` moves onto it.
