## Description

Channel hints on PostgreSQL (TKT-YK30D1) go out on the `rela_channels` NOTIFY
channel. NOTIFY delivers every payload to every listener on the database, in
every schema. Schemas that share a database therefore see each other's hint
metadata: channel keys (entity ids) and principal keys of addressed users and
readers. TKT-YK30D1 documents this in `docs/postgres-backend.md`.

Entity ids already travel this way on `rela_changed`. Principal keys are new.

## Options

1. Keep principal keys out of NOTIFY. Addressed and read-mark hints say only
"inbox changed" for a channel; receivers replay their inbox subscriptions. Costs
some extra replay work.
2. Store the hint in a table inside the schema and send only a row id.
Full isolation; needs a table, a migration and cleanup.

Hashing does not help: the salt (schema name) is public and principal ids are
guessable.

Found by an automated security review of the TKT-YK30D1 commit.
