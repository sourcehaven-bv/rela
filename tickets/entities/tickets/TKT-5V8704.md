## Description

**PR 2 of 3** (see FEAT-OJ8L0H) — the primary ask. Tokens are TKT-8VVBRI (PR 1),
icons are TKT-8GUI60 (PR 3). Depends on PR 1 landing first so this PR
restructures layout without also churning radius/font literals.

**Root cause.** The detail page's property block is not a grid —
`SectionEditForm.vue:304`:

```css
.properties-list { display: flex; flex-wrap: wrap; gap: 16px 32px; }
.property-item   { display: flex; flex-direction: column; min-width: 200px; }
```

A wrapping flex row of grow-able `min-width: 200px` items. Consequences:

- Items stretch to fill each row, so **column edges differ line to line** —
no vertical axis to scan down.
- Width is independent of content: a date, an enum and a name get identical
boxes, so short values float in wide fields.
- The wrap point is whatever the viewport allows, so the trailing field
(`ESTIMATED HOURS`) is **orphaned** at 1440px.

**Adjacency is currently implicit** — decided by viewport arithmetic rather than
intent. That is the actual defect.

`.properties-list` / `.property-item` is also redefined independently in three
components, each with different rules, all scoped so they never actually share:

| File | `min-width` | Extra |
|---|---|---|
| `forms/SectionEditForm.vue:304` | 200px | — |
| `common/PropertyDisplay.vue:108` | 120px | `.property-long` -> 100% |
| `forms/SidePanel.vue:295` | (third variant) | — |

This is why the detail page does not align *with itself*.

### Chosen model (Filament-style)

A 12-column grid where **fields default to full width (single column)** and an
author opts fields onto a shared row by declaring a span:

```yaml
fields:
  - property: title          # full width (default)
  - property: description    # full width
  - property: status
    span: 4                  # ┐
  - property: priority       # ├ one row
    span: 4                  # │
  - property: due_date       # ┘
    span: 4
```

Labels sit above their field (as in Filament), which also avoids a long label
starving a `max-content` label column. Adjacency becomes **explicit and
authored**: those three share a row because someone said they belong together,
not because three boxes happened to fit.

### Applies to views AND forms (RR-OYENHV)

`ViewSectionField` (`config.go:574`) and `FormField` (`config.go:176`) are
disjoint structs; **both** gain `Span`. The Filament reference is itself a form
builder, and `/form/create_ticket` was among the sloppiest surfaces found — a
span model that doesn't work on forms would read as half-built.

### Plumbing (RR-OYENHV)

The config struct is **not** what reaches the SPA. `SectionFieldData`
(`sections.go:56`) must carry `Span` too, and it is constructed at **two
near-identical sites** — `sections.go:186` (`buildSectionEntityData`) and
`sections.go:228` (the entry-source `properties` branch). Adding it to one only
would make spans work on the detail page and silently vanish on card/list
sections. Factor the duplicated literal blocks while there.

`default_view.go:46` auto-generates a properties section for any entity type
without a configured view and authors no spans — so the **single-column default
is the common case** and must look good with zero authoring.

### Validation (RR-IUMZV8)

Spans are validated **loudly at load**, not silently clamped.
`validateViews`/`validateForms` reject a span outside 1..12 with an indexed
message, consistent with every other validator in `ValidateConfig`
(`validate.go:120`), which even suggests corrections for typo'd keys. The
frontend still defends independently (out-of-range -> full width) for
hand-crafted API responses, but a bad config fails at startup.

### Row behaviour (RR-P2QU85) — specified, not left to implementation

- Spans that don't fill a row leave the remainder **empty** (no stretch) —
CSS Grid's natural behaviour and Filament's. Documented so nobody "fixes" it.
- A field that doesn't fit the remaining columns wraps to the next row, leaving
the remainder empty.
- Below a defined container width every item collapses to full width.
- **ACL interaction is safe**: git-crypt inaccessible fields are *rendered* as
an `InaccessibleField` lock placeholder, not removed
(`sectionEditFields.ts:96`), so they hold their grid cell and nothing reflows.
`visible:`-redacted properties are dropped from the wire, but per CLAUDE.md
field-level redaction hides *values only* and makes no claim to conceal which
properties exist (the metamodel is served over the API), so a resulting gap
leaks nothing. No layout-based oracle.

### Not in scope for this ticket

`SectionEditForm` already picks `mode="edit"` vs `mode="display"` per field from
the ACL verdict (`row.writable`, lines 242-272). Everything looks editable in
the prototype only because `alice` holds the editor role. Inline autosave
editing is a real feature and must be preserved unchanged.

## Acceptance criteria

1. Detail-page properties render **single-column (full width) by default**,
labels above fields, with no orphaned trailing field at any viewport.
2. An optional `span` on both `ViewSectionField` and `FormField` places fields
side by side on a 12-column grid; omitted `span` means full width.
3. A span outside 1..12 is a **load-time config error** with an indexed
message; the frontend independently falls back to full width.
4. `Span` survives YAML -> config -> `SectionFieldData` -> view JSON on **both**
construction sites, verified for a card/list section as well as the detail page.
5. The auto-generated default view (`default_view.go:46`, which authors no
spans) is legible unaided.
6. Row behaviour matches the spec above: unfilled remainder stays empty,
non-fitting field wraps, narrow viewport collapses to full width.
7. The three `.properties-list` definitions are unified into one shared
stylesheet, with intended visual deltas to SidePanel/PropertyDisplay documented.
8. ACL behaviour unchanged: a non-writable field does not become editable, and
`InaccessibleField` stays visually distinct and holds its grid cell.
9. Both themes verified visually across the affected views.
10. No regression in frontend unit tests, Go tests, or the e2e suite.

## Out of scope

- Design tokens (TKT-8VVBRI, PR 1) and icons (TKT-8GUI60, PR 3).
- **Label humanization / casing** (`due_date` -> `Due date`, and the humanize
regex duplicated across 7 files) — separate PR.
- Changing which fields are editable, or any ACL verdict logic.
- Mobile responsive work (`FEAT-M448` / `FEAT-U9GY2`) beyond AC 6's collapse
rule.
