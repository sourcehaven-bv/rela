[[TKT-6NDSH9]] (write surface completion).

## What

**Extraction (pure structural).** New `viewsHandler` (views_handler.go) owns the
read-only view-assembly surface — 16 methods moved off `App`:

- View traversal engine (views.go, receiver change in place): `executeView`,
`applyViewTraverse`, `traverseViewOnce`, `traverseViewRecursive`,
`filterEntities`.
- Section builders (sections.go, in place): `buildSectionEntityData`,
`buildSections`, `executeSidePanel`, `resolveSectionButtonsWithTraverse`.
- Endpoints (moved from api_v1.go): `handleV1Views`, `handleV1SidePanel`,
`handleV1Sidebar` + `navEntryToSidebarItem` + the `sidebarCounts` machinery (its
`app *App` field retargeted to `h *viewsHandler`).
- Form-resolution helpers (from app.go): `editFormForType`, `createFormForType`;
plus `resolveRelationColumnValues` (from helpers.go).

Three receiver-free helpers became package functions: `resolveLinkTarget`,
`findListByEntityType`, `resolveRelationWidgets`.

Collaborators mirror attachmentHandler/writeHandler: fixed service handles by
value (store/reader/serializer/affordances/logo — never test-swapped), schema
snapshot + Services bundle as closures, and `App.gateReadOrNotFound` as the
shared `gateRead` closure so the uniform-404 invariant (RR-NGMI) cannot drift.
Read-only surface — NO writeMu. `commandHandler.executeView` now binds
`app.views.executeView`; wiring parity NewApp ↔ rebindApp.

**Rebase note (post-#1228 / #1235 develop).** The extraction is structural
except for the ACL read-out seams that had to be carried across: while this
branch was open, develop landed the DEC-ZBI39P / BUG-R9EHKV gating on the `App`
copies of `executeView`, `resolveRelationColumnValues`, and `handleV1Views`'
mention resolution. All three live on `viewsHandler` now, so the handler gained
two collaborators rather than inheriting the pre-fix bodies:

- `viewReader visibility.Reader` — wired from `app.viewReader` in both NewApp
and rebindApp. `resolveRelationColumnValues` collects targets and routes them
through `viewReader.Filter` before deriving titles, `executeView` filters each
collection through it, and `handleV1Views` passes it to `collectMentions`
(whose signature gained a `visibility.Reader` in #1235).
- `redactor()` — the handler-local equivalent of `appRedactor(a)`, which takes
`*App` and so could not follow the method to the handler. It returns the same
`affRedactor` over the handler's own `affordances`, keeping `executeView`'s
entry redaction intact.

Taking the extraction's side verbatim during either rebase would have silently
reverted a leak fix. Regression pins, each verified to fail when the
corresponding seam is bypassed: `TestACLViews_RelationColumnRedactsHiddenNeighborTitle`
and `TestACLViews_RelationColumnDropsUnreadableNeighbor` (relation-column
titles), `TestV1Views_MentionsPopulated` (the mentions wiring).

**Deletion (closes GitHub #1043).** The server-rendered nav-enrichment path —
`NavItem`/`NavGroup`/`NavElement`, `enrichNavEntry`, `navElements`,
`activeListForEntityType`, `activeListFromReferer`, `resolveActiveList` (5
methods + 3 types) — had NO production callers since the SPA took over
navigation, and `enrichNavEntry` counted entities from the RAW store, leaking
existence counts of ACL-hidden entities. The live sidebar
(`viewsHandler.handleV1Sidebar`) routes every count through the ACL read scope
(TKT-VMD8) and is pinned by `TestACLSidebar_CountsMatchList`. Deleting the dead
path removes the leak entirely.

- **`App`: 114 → 90 methods** (16 moved + 3 package-leveled + 5 deleted);
`//plimsoll:max-methods` ratcheted 114 → 90.
- Follow-up noted: `userStateStore.loadUIState`/`saveUIState` lost their last
production consumer (navElements) — UIState collapse-persistence is now dead
weight pending a UX decision.
