## Description

A flows.yaml trigger can set properties but cannot remove one. A to-do that is
reopened keeps its `completed_on` date. Add `unset:` to the `set` output: a list
of property names the trigger removes.

```yaml
outputs:
  - set:
      unset: [completed_on]
```

The removal folds into the write the trigger fires on, exactly like `set`: the
entitymanager applies it as `entity.Patch.MetaUnset` semantics (delete the key)
on the in-flight entity or, on create, on the re-read stored row inside the
compare-and-swap. No separate read-modify-write.

Load-time validation: an unknown property, a property both set and unset, a
computed, file or external-ref property.

## Acceptance

- `set.unset` removes the named properties on update, create and copy.
- `set` may hold only `unset`.
- Load errors for the cases above.
- Engine test named after the behaviour; docs in docs-project.
