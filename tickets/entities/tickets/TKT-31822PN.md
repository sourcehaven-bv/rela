## Description

A customer portal built on rela shows page chrome that only makes sense to
staff:

- The dashboard always shows the Validation card. It links to the project-wide analysis.
- The entity page header always shows History and "Add to pile".

An operator cannot switch these off or limit them to a role.

## Proposal

Add a toggle to data-entry.yaml for each of these built-in elements. It takes
`true`, `false` or `{permission: <name>}`:

- `validation:` on `dashboard:` and on each entry of `dashboards:`.
- `entity_header.history` and `entity_header.add_to_pile` at the top level.

The default stays as today: shown. The server resolves the gate per principal.
`/api/v1/_dashboard` carries `validation`, and `/api/v1/_sidebar` carries
`entity_header`.

A permission gate is a UX filter, not access control. The history and pile APIs
keep their own ACL. The configuration is not a secret.

Found while configuring the harbourmaster customer portal (gaps 2 and 8).
