## Description

Observed 2026-10-12 on the tickets project: an automation created PLAN-3623CQ
(file on disk) while another rela CLI process was running. Afterwards every CLI
call answered "entity not found: PLAN-3623CQ" until
tickets/.rela/fsstore-index.json was deleted. The cache is trusted when
directory mtimes match (internal/store/fsstore/fsstore.go
Config.IgnoreIndexCache doc), so a process that loaded the tree before the
create and wrote the index after it can record the new directory mtime without
the new file.

## Reproduce (suspected)

Run many concurrent rela create/update calls against one fs project; check that
every created entity is found afterwards without deleting the index.

## Fix direction

Record per-directory mtimes captured BEFORE the scan, write the index
atomically, or validate entries against a directory listing count.
