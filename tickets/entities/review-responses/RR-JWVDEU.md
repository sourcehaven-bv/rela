title: warnIfScanCannotRun should take a one-method interface so the sandbox-error branch is testable on every platform
finding: 'warnIfScanCannotRun takes a concrete *attachment.CmdRunner solely to reach SandboxErr(); the call site comment in app.go even flags that the narrow CommandRunner interface carries no sandbox accessor. Per CLAUDE.md''s interfaces-at-the-call-site rule this should be a locally declared `type sandboxReporter interface{ SandboxErr() error }`. The consequence is not merely stylistic: because the tests must construct a REAL CmdRunner, the `runner.SandboxErr() != nil` branch — the exact branch that fires in the systemd scenario this whole ticket exists for — is never exercised. TestWarnIfScanCannotRun_SilentWhenSandboxUsable t.Skips when the host has no sandbox, and the healthy table case passes only because macOS sandbox-exec happens to work here. With an interface, a fake reporter covers both branches deterministically on every platform, and this subsumes RR-Q4P93R''s portability failure. Related: the `runner == nil` disjunct is defensible defensively, but the call site has exactly one producer (`runner, rerr := NewCmdRunner(...)`), so the nil-without-error case the test documents cannot actually occur, and that branch logs `err=<nil>`.'
severity: significant
resolution: 'warnIfScanCannotRun now takes a call-site-declared `sandboxReporter interface{ SandboxErr() error }` instead of *attachment.CmdRunner, per CLAUDE.md''s interfaces-at-the-call-site rule. Tests use a stubReporter, so BOTH branches — including the unusable-sandbox branch this ticket exists for — run deterministically on every platform with no t.Skip. Test matrix grew from 4 cases to 5 plus the nil-metamodel case, adding the previously-uncovered `sandbox unusable → warn` and `scan off + sandbox unusable → silent`. This subsumes RR-Q4P93R. IMPORTANT follow-on found while making the change: passing a nil *CmdRunner into an interface parameter yields a NON-nil interface (typed-nil trap), which would have skipped the constructor-failure branch and then called SandboxErr on a nil pointer — the exact panic RR-U6ZTOM warned about, reintroduced by the refactor. The call site now assigns the interface only when rerr == nil, with a comment naming the trap.'
status: addressed
