title: Apple-fixture comparison is a six-property whitelist; invert it, and move the true round-trip to the adapter
finding: |-
    On AC6 (the deliberate deviation): the reviewer mutation-tested the substitute and it has real teeth — dropping COMPLETED, renaming DUE→DTSTART, dropping DESCRIPTION and dropping URL were ALL caught. So it is not a test a trivially-broken renderer passes, and the decision not to add a parser to a render-only leaf package stands.

    The hole is specific: TestRenderTodo_MatchesAppleSemantics compares a WHITELIST of six properties, so it can only catch regressions in properties someone remembered to list. Cardinality, ranges, and any newly-added property are outside it by construction.

    Fix: invert it — iterate the properties PRESENT IN THE FIXTURE, skip a documented ignore-list (PRODID, DTSTAMP, CREATED, LAST-MODIFIED, X-APPLE-SORT-ORDER, DTSTART), and require the rest to match. A new Apple property then fails loudly instead of silently.

    Also free coverage: the test never compares DESCRIPTION or URL even though both are in the model and the fixture. URL would match (fixtureProp handles Apple's URL;VALUE=URI: normalisation) — add it. DESCRIPTION cannot be compared directly because the test's model uses a truncated string; either use the full fixture text or drop the pretense.

    Separately, track the REAL round-trip as an explicit follow-up on TKT-MF1CWZ: put a parse-and-re-render test in the adapter package where go-ical already lives, importing these same fixtures. Otherwise AC6 quietly becomes "never done".

    Helper nits: fixtureProp (vtodo_apple_test.go:33) returns "" for both "absent" and "present but empty", and TestApple_ClientCreatedTodoIsBareUUID:115 relies on "" meaning absent — correct for these fixtures but one Apple release from being wrong; return (string, bool). The first-match prefix logic is fine (COMPLETED does not mis-match PERCENT-COMPLETE, verified) but is non-obvious.
