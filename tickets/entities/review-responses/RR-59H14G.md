title: '"No entry applies: stored, no move" is safe but silent; add a load warning and say it in the agent docs'
finding: 'With a required enum whose values every guard covers, the PoC always moves. An optional or uncovered value stores a 201 with no notice. With expect_generation (Admit runs first, channels/session.go:384-402) the post is accepted and the generation does not change, so a retry works and nothing is lost. That makes the choice safe. However, an agent that reads only the 201 waits on a session that never moved, and the post_message description (internal/mcp/tools_channels.go:325-334) says nothing about it. Fix: (1) a load warning at on.<type> when every entry has a `when` (no catch-all), naming the risk; (2) one sentence in post_message and docs/realtime.md: "if no entry applies the message is stored and the session stays; compare session.generation in the answer". Keeping Q1''s strict opt-in as a follow-up is fine.'
severity: minor
resolution: Added a load warning at `on.<type>` when no entry is a catch-all, and the no-match sentence (compare session.generation) to MCP `post_message` and docs/realtime.md.
