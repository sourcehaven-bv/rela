id: RR-GW9711
type: review-response
title: 'Relation label chain ignored direction: incoming pickers showed the outgoing label'
finding: 'The new fallback chain in RelationPicker.vue and RelationCards.vue was `field.label || relationType.label || field.relation`, which is direction-blind. relationType.label is the OUTGOING label, so an unlabelled `direction: incoming` picker rendered ''blocks'' where it should render the inverse (''blocked by''). Both components already branch on isIncoming elsewhere for from/to resolution, and the server does exactly this direction-aware resolution in internal/dataentry/export.go relationDisplayLabel. Not a regression (the prior chain was equally direction-blind) and nothing is destroyed since the migration only strips against RelationDef.Label — but these were the lines being touched to make correct, and they were left half-correct.'
severity: minor
resolution: 'Both components now insert the inverse label for incoming direction: field.label || (isIncoming ? relationType.inverse?.label : undefined) || relationType.label || field.relation. Mirrors the server-side precedence. Added two RelationPicker tests: inverse label preferred for incoming, and graceful fall-through to the outgoing label when no inverse label is authored.'
status: addressed
