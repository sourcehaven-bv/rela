title: clamd.conf is bound into attachment transform commands too, not only scan commands
finding: 'NewCmdRunner builds ONE cmdexec.Runner shared by Scan and attachment-level cmd: transform steps (applyCmdStep, internal/attachment/command.go:104), and WithExtraReadOnly binds into EVERY command that runner executes. So exiftool/qpdf/etc. invoked as attachment transforms — which process attacker-supplied bytes — receive a read-only bind of /etc/clamav/clamd.conf they have no need for. Blast radius is narrower than first assumed: internal/transform/engine.go:38 and internal/dataentry/document.go:653 each construct their OWN runner with no WithExtraReadOnly, so pandoc/ghostscript and the view-export/LaTeX path (the paths the verified \input{/etc/passwd} exfiltration was demonstrated against) do NOT get this bind. Content risk is low (stock clamd.conf is 644, holds paths and tunables, and freshclam.conf is correctly excluded), but a hardened install may set non-default LocalSocket/TemporaryDirectory paths, which is host-topology disclosure to a third-party parser. Attack path: malicious PDF uploaded to a file property carrying a transform: [{cmd: [qpdf, ...]}] step, parser coerced into reading clamd.conf, contents embedded in transform output, downloaded by the uploader. Requires an attachment cmd: transform to be configured plus a parser with a file-read primitive.'
severity: significant
status: addressed
resolution: 'Scoped by documentation rather than by splitting the runner. Verified the reviewer''s claim about blast radius: internal/transform/engine.go:37 and internal/dataentry/document.go:653 each build their own cmdexec.Runner with no WithExtraReadOnly, so pandoc/ghostscript and the export/document paths (the ones the LaTeX include-file exfiltration was demonstrated against) genuinely never see these binds. The exposure is limited to attachment cmd: transform steps sharing the scan runner. DefaultScannerConfigs godoc now states that scope explicitly, so the next person extending the list knows who else receives it. Splitting into separate scan/transform runners was considered and deferred: it is a larger change than this ticket warrants, and the residual risk is one mode-0644 file of paths and tunables.'
