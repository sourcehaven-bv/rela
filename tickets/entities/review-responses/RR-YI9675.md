title: Removing then re-adding a type in one session brings soft-deleted entities back as live
finding: 'internal/store/fsstore/schemas.go dropUndeclared deletes the type''s families from s.marked in memory only; pending-deletes.json still lists them. If a later reload declares the type again (an operator comments a type out and back in), indexAnnounced finds no mark (markedTaken is false), so the soft-deleted entities rejoin the live index and are announced as EventEntityCreated. A restart before any other soft delete re-hides them from pending-deletes.json, so the session and the restart disagree. Purge also never removes those files, because the marks are gone. Fix: keep dropped families aside (for example a map of undeclared marks restored when the type returns), or have SetSchemas consult readPendingDeletes ids before indexing a found file. Add a test: soft delete, remove the type, re-add it, assert GetEntity is not found.'
severity: minor
resolution: Soft-delete marks of a removed type are kept; while the type is undeclared, list, unmark and purge skip the family. Test covers soft delete, remove, re-add.
status: addressed
