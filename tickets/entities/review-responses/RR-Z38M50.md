id: RR-Z38M50
type: review-response
title: fsstore hashes files on every listing without ctx or deduplication
finding: ListFamilyAttachments read and hashed every unhashed file synchronously, ignored ctx, and repeated the work for concurrent callers, including name-only callers in the write path.
severity: significant
resolution: 'Hashing now honours ctx (a ctx-checking reader and a check per file) and concurrent lists share one read per file version through singleflight keyed on path, size and mtime. A file is hashed once per version per process and the result is cached in the index. A separate hash-free listing was not added: it would widen store.Store on four backends for a one-time cost per file.'
status: addressed
