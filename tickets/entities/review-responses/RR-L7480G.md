type: review-response
title: Close-only trigger job mark on a shared-target branch resolves to the wrong entry and records a spurious transition_removed failure
finding: 'branches.go:106 (duplicates) allows two entries with the same to when neither has outputs, e.g. on.close: [{to: closed, roles: [lead]}, {to: closed, by: trigger}] with on_final: close. A trigger post fires entry [1]; triggerMark (outputs.go:378) writes a job mark (Job: true, Close: true) because the target closes. resolveMark (outputs.go:521) looks the entry up with TransitionTo(from, type, to), which returns the FIRST entry with that target, entry [0], a person entry with t.Job() false. The check mark.Job && !t.Job() then marks the plan removed, and run() (outputs.go:676) appends an OutputFailed result with OutputCodeTransitionRemoved before the close runs. Every such auto-close is reported as a failed transition. The fix is one of: refuse duplicate targets when the target closes the channel (treat closes like outputs in duplicates); have resolveMark accept any entry with that target whose Job() matches mark.Job; or skip the Job check when the mark has no outputs. Add a resolveMark/runner test for this config.'
severity: significant
resolution: 'resolveMark now picks the entry through markEntry, which takes the first entry to mark.To whose Job() matches a job mark, and TestOutputs_SharedTargetTriggerCloseMark (on_final: close, lead and trigger entries to closed) pins that the close runs with no transition_removed result.'
status: addressed
