title: analyze schema --cleanup broken on every new-name project
finding: 'internal/schema/ was missed entirely by the rename sweep. internal/cli/analyze.go:732 was updated to derive projectRoot from svc.Paths.SchemaPath, but it passes a ROOT into schema.ExecuteCleanup, which reconstructs the filename at cleanup.go:171: `metamodelPath := filepath.Join(projectRoot, "metamodel.yaml")`. On any schema.yaml project (i.e. every project created after this change) cleanup fails with `failed to update metamodel.yaml: no such file or directory` — naming a file the user has never seen. Latent escalation: ExecuteCleanup applies metamodel changes FIRST and returns early on failure, so today it fails clean; reordering or adding a change type would produce a partial write (data-entry.yaml stripped of references to types still present in the schema). Additionally plan.MetamodelChanges[].File is hardcoded "metamodel.yaml" in ~10 places across analyze.go/cleanup.go and is printed straight to the operator at analyze.go:720. Fix: stop passing a root and reconstructing a name — pass the resolved schema path into ExecuteCleanup, and populate File from the resolved basename. This is exactly the class of bug the resolved-path design was meant to prevent, in the one package the sweep skipped.'
severity: critical
resolution: 'Fixed by removing the reconstruction rather than teaching it both names. ExecuteCleanup now takes the RESOLVED schemaPath alongside projectRoot instead of rebuilding filepath.Join(projectRoot, "metamodel.yaml"), and its error message uses filepath.Base(schemaPath). PlanCleanup takes a schemaFile basename parameter so the operator-facing Change.File labels name the file that actually exists. Call sites in internal/cli/analyze.go pass svc.Paths.SchemaPath and svc.Paths.Root. Verified end-to-end with a real binary on a schema.yaml project: cleanup --dry-run reports ''schema.yaml: remove_entity_type ...'' and the APPLY path (previously ''failed to update metamodel.yaml: no such file or directory'') now succeeds and edits the correct file. Test call sites updated to use schema.yaml fixtures.'
status: addressed
