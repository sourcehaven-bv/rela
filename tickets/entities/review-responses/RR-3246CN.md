title: Graph checks treat a shadowed entry as fireable, so `answers` can pass a session that waits forever
finding: 'The plan says every walker (answers, deadlineReset, returnsTo, answerGrants) walks every entry independently through fireableBy/isAnswer (waiting.go:171-197, 206-267). Under first-match, an earlier entry with no `when` whose poster rule admits role r shadows every later entry for r. The unreachable check only refuses entries that are shadowed for every poster. Example in a state with waiting_for [owner]: [{to: plan-review (re-entry), roles: [owner]}, {to: working}]. Entry 2 is reachable by the runner, so it is not refused, and `answers` counts it as the owner''s answer. The owner always hits entry 1, though, and the session waits on them forever. That is exactly what the check exists to refuse. deadlineReset and answerGrants can likewise report false positives and false negatives. Fix: give the walkers a per-role view, fireableBy(st, mt, i, role), that is false when an earlier unguarded entry admits that role (and the same for triggers in jobEdges/transitionCause). Add an AC 7 case for a shadowed answer.'
severity: significant
resolution: Added a per-role helper `firesFor` that every graph walker uses (answers, deadlineReset, returnsTo, answerGrants, jobEdges, jobOutputs, transitionCause), plus an AC 7 shadowed-answer case.
status: addressed
