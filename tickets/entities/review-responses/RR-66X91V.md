Since MigrateWithFS never touches schema.yaml on a non-legacy project absent a content migration — and the fixture has none — the assertion holds trivially. Deleting renameLegacySchema entirely, or the both-present guard, leaves this test passing. It pins nothing. Its own comment admits the drift (''Either way the invariant is the same'') while keeping a name that claims to test a refusal. Downstream of RR-URUZIS: once the both-present behaviour is actually implemented, this must assert the specific outcome.'
severity: significant

Added TestSchemaNameStatus covering what `migrate --check` sees for both an orphaned and a clean project. Each assertion now fails if the corresponding code is removed, which the old accept-either-outcome version did not.'
