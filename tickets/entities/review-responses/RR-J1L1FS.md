title: rela.request.query._all and its per-key lists are mutable — the freeze does not reach nested tables
finding: '[security] internal/lua/request.go:105-106 builds the repeated-query-value map (`all`, plus a per-key `list` table for each repeated key) with RawSetString and then freezes only the enclosing `query` table via freezeTable. freezeTable installs a __newindex guard on the table it is given; it does not recurse. So `query` and `headers` are read-only, but `query._all` and every `query._all[key]` list are freely writable from a script. VERIFIED by probe: `rela.request.query.tag = "evil"` raises "attempt to modify a read-only table", as does assigning to headers or adding a new query key — but `rela.request.query._all.tag = "evil"` succeeds silently. This contradicts the stated contract in the doc comment at request.go:58 ("Frozen with freezeTable like rela.principal: the table is the record of what actually arrived") and the rationale in TestWithRequest_ReadOnly, which says a script that rewrote the request would make a later read (an error envelope, an audit line) disagree with the wire. Severity is minor rather than significant because nothing in the current code re-reads rela.request after the script runs — the impact is a broken invariant rather than a demonstrated disclosure or corruption. It becomes significant the moment anything (an audit line, an error envelope, a retry that re-reads the table) trusts the post-script value, which is exactly what the comment promises is safe. Existing coverage misses it: TestWithRequest_ReadOnly only asserts the TOP-LEVEL table. Fix: freeze `all` and each per-key `list` before inserting them (or make freezeTable recurse for this construction), and extend the read-only test into a table over query, headers, _all and a per-key list so the nested cases cannot regress. Separately verified and NOT a finding: a literal `_all=x` query parameter does not collide — `query.RawSetString("_all", all)` runs after the loop, so the repeated-values map deterministically wins and the attacker-supplied scalar is discarded rather than shadowing it.'
severity: minor
resolution: 'Fixed in ea37f09a on feat/lua-request-actions-TKT-EFMRQM. Each per-key list and the enclosing `all` map are now passed through freezeTable before insertion, so the freeze reaches every level rather than stopping at `query`. Verified failing-first: reverting to the raw RawSetString form makes TestWithRequest_ReadOnlyIsNotSkinDeep catch 2 nested mutations (query._all and a per-key list); restoring returns the package to green. The old TestWithRequest_ReadOnly asserted only the top-level table — which is exactly why this survived — so it is replaced by a table over every nested path: top-level field, existing query key, new query key, header, the _all map, and a per-key _all list. Also added TestWithRequest_AllKeyIsNotShadowable, pinning the separately-verified non-finding that a literal `_all=` parameter cannot displace the repeated-value map. That test asserts inside Lua rather than through captured print output, so it does not depend on how the runtime happens to wire stdout.'
status: addressed
