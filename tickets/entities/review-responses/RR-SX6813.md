title: metamodel's copy of filter's operator set can drift silently
finding: Security review, flagged as a correctness/maintenance concern rather than a security one. wherePropertyName (internal/metamodel/loader.go) reimplements filter's operator splitting locally because arch-lint forbids metamodel importing internal/filter. The operator list and longest-first ordering match filter.go today, but a future operator added to internal/filter would drift here silently. A drifted parser returns "" and skips the check, which loses a load-time diagnostic without weakening a runtime gate.
severity: minor
resolution: 'Hoisted filter''s operator table to a package var and exported filter.Operators(); metamodel exports WhereOperators(). A new TestOperatorSetsAgree in internal/filter fails if the two sets diverge, with a message naming both and pointing at the copy to update. The guard lives in filter because that is the definition side. Mutation-tested: adding a bogus operator to filter fails the test. Also documented on wherePropertyName that an unrecognised clause SKIPS rather than errors, so drift can never reject a valid schema.'
status: addressed
