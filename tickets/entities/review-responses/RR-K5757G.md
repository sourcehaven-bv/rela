id: RR-K5757G
type: review-response
title: applyOrientation (hand-written EXIF parser) runs outside the recover() guard
finding: applyOrientation and its exifOrientation→orientationFromTIFF→exifAPP1 chain run on the caller's goroutine at imgproc.go:255, NOT inside the recover()-guarded worker in decodeBounded. The parser is verified panic-free today (40k fuzz execs clean), so it is not a live bug, but it is the one place a panic on attacker-controlled bytes would crash the process. The 'EXIF parser never panics' invariant is load-bearing and enforced only by manual review; any future unchecked index reintroduces a process-crash DoS.
severity: significant
resolution: applyOrientation now has a deferred recover() that falls back to the un-transformed image (orientation is best-effort). A parser bug can no longer crash the write path. Additionally added FuzzExifOrientation + FuzzOrientationFromTIFF seeded with valid EXIF, which exercise the parser directly (1.19M + 452k execs, no panics).
status: addressed
