[security] Defense-in-depth only — the attack path requires a caching proxy that
caches POST responses, which is unusual. Raised because the surrounding codebase
already takes this posture deliberately: attachment and export downloads set
`no-store` for the same reason, and this route is outside the `/api/` prefix
where `noCacheMiddleware` would otherwise supply it.

One-line fix at `webhook_routes.go:168`.
