title: 'PR-B: migration dropped derived unique indexes into a best-effort recreate - self-perpetuating enforcement gap'
finding: '0011 dropped all rela_derived_uniq__* indexes and deferred recreation to the boot reconcile — which is best-effort by design (store-open must never fail; errors are logged and swallowed). Reviewer demonstrated the full failure mode on an upgraded DB: duplicates insert freely in the gap, and once one exists the recreate fails forever with a swallowed WARN. Multi-process rolling upgrades write through the window.'
severity: significant
resolution: 'The migration now REBUILDS each index inside its own transaction by appending the narrowed predicate to the index''s recorded indexdef: the constraint is never absent, the recreate cannot fail on existing data (the new predicate is strictly narrower and every existing row is a default state), and the boot reconcile finds the name present with a semantically identical definition. Validated end-to-end on a real 0001-0010 database with a seeded derived index: rebuilt predicate correct, state row sharing its family''s unique value inserts, duplicate default row still rejected. A no-WHERE index under the prefix fails the migration loudly — deliberate, documented.'
status: addressed
