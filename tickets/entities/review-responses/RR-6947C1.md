id: RR-6947C1
type: review-response
title: Empty-Endpoints widening removed the ACL read gate's fail-closed backstop
finding: 'Making empty RelationPredicate.Endpoints mean ''any endpoint'' (needed for absence queries) is a WIDENING, not a narrowing. internal/acl/readquery.go composes its HasInbound predicate with Endpoints: globals.Members, and walkMembers returns nil when principal.User == "". Before this change an empty member set matched nothing, so the gate denied; after, it would degrade to ''entity has a conferring edge from ANYONE'' -- a read bypass. Currently unreachable in production because Declarative.ForPrincipal rejects unstamped principals, but that guard lives in a different file with no cross-reference, so the gate went from two-guards-deep to one, silently. A future anonymous-read mode or a system principal skipping ForPrincipal would open every row with no test failing.'
severity: significant
resolution: 'Added an explicit fail-closed guard in readQuery: an empty globals.Members now returns ReadQueryResult{DenyAll: true}, stating the invariant locally rather than depending on upstream validation. Documented the widening on store.RelationPredicate.Endpoints so callers deriving endpoints from a principal know they must guard. Added TestReadQuery_FailsClosedOnEmptyMemberSet (in-package, constructing a Request directly since ForPrincipal rejects the scenario by design) and mutation-tested it: removing the guard makes it fail.'
status: addressed
