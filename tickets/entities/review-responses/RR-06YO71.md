title: Move the message-level prop rules too, not only the per-value ones
finding: 'The plan moves normalizeProp and its helpers, but validateProps stays in realtime (internal/realtime/validate.go:41-84). validateProps holds the rules that a JSON null or an empty list is an absent property, that required is checked after that, the MaxProps cap, and the encoded size against message_bytes. AC 3 would re-implement all of these in realtimecfg. That is the drift the plan itself rejects under ''duplicate a subset''. For example, a preset of tags: [] on a required list must be refused because the runtime treats it as absent. Fix: move the core as MessageType.NormalizeProps(in, maxBytes) returning the stored map, the size, the refs and sentinel errors (ErrTooManyProps, ErrTooLarge). realtime maps those errors to its DenialError types. The move is otherwise clean: the code is pure, it puts PredicateValue beside messageRecordType, and the arch-lint additions (texthazard, xnorm; entity is common at .go-arch-lint.yml:388) are exactly what the imports need. Nothing from runtime leaks into config.'
severity: significant
resolution: The core of validateProps moves as MessageType.NormalizeProps(in, maxBytes) with sentinels ErrTooManyProps and ErrTooLarge, which realtime maps to its existing denials, so the rules exist once. AC 3 now covers null, empty-list and prop-count cases through it.
status: addressed
