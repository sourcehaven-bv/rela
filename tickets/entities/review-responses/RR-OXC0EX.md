title: Compose click that discards an edit likely loses compose mode and can post the preset over visible fields
finding: 'useSessionDecisions.ts:433-441 records formDecision.compose synchronously right after d.composer.discardEdit(), so the composer receives editing=null and the new compose prop in the same render flush. In RlChannelComposer.vue the compose-key watcher (line 261, created first) sets selected=c.type, then the editing watcher (line 372) restores the stashed pre-edit selection at line 383 (typically the default type, not c.type). The name watcher (line 273) then sets droppedKey, and the select emit may reach onComposerSelect with the other type and clear the record. The app''s later select(view.messageType) re-selects the type, but composing stays undefined because droppedKey===key. The result is either a plain form with no preset and no generation, or, if the select emit did not clear the record, a form that renders the given fields as editable while sendComposer (line 259) silently overwrites what the user typed there with the preset. The old type-button path does not hit this because it records after the await. Only the declined branch is tested (useSessionDecisions.test.ts:950), and ComposeModeDuringEdit (stories:990) never ends the edit. Fix: in openForm, record the compose decision after the edit restore has flushed (await nextTick after discardEdit), or make the editing watcher prefer a live compose.type when it restores. Add a ChannelsPanel or story test: start an edit on another type, click the compose preset, accept the discard, and assert the strip shows and the Send carries the preset.'
severity: significant
resolution: "addressed\tTwo fixes. The composer's select event now reports a compose type that has not been applied yet, and when an edit ends it restores that type instead of the one the edit put aside. Before, the restored type reached the app first and cleared the record. openForm also waits one tick after discardEdit before it records compose. New tests: a ChannelsPanel test (edit a card, click the compose preset, accept the discard; the strip shows and the Send carries the preset and generation 4), a ComposeModeEditEnds story, and a unit test for the accepted discard. The panel test and the story both failed before the fix."
status: addressed
