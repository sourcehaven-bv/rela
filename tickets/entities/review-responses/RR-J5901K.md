title: The racy window compares an FS-clock mtime with the local clock
finding: Point 4 checks the observed mtime against the capture time from an injectable local clock. Git's racy check compares against the index file's own mtime, so both sides come from the filesystem's clock. On a network share or a VM bind mount whose server clock lags the local clock by more than the window, a directory changed just before the open looks old, is trusted, and a same-tick write after the listing is missed on a coarse-mtime filesystem. Treat an mtime in the future, or within the window of now, as racy; and either derive filesystem time from a file the store writes (for example the mtime of the cache file it saves, with the local-clock offset applied to the capture time) or record the clock assumption under Risks next to the network-filesystem note.
severity: minor
resolution: Resolved by removing the cache; no racy-window logic is planned.
status: addressed
