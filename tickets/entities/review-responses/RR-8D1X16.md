type: review-response
title: 'icon: None suggested "done" — the new error message recommended a green check mark for the one typo it was built to catch'
finding: |-
    `suggestIcon` lowercases the input and scans `ValidIconNames`. But `NoIcon` is deliberately NOT in `ValidIconNames`, so `none` was never a suggestion candidate. `editDistance("none", "done") == 1`, so `done` won.

    Verified empirically — all three of `None`, `NONE`, `nOnE` produced:

        unknown icon "None" (did you mean "done"?); use "none" for no icon, ...

    YAML is case-sensitive and `None` is a spelling authors type by reflex. The author takes the suggestion and their "Blocked" swimlane renders a green check mark.

    The message does also say `use "none" for no icon`, but the parenthesised suggestion is the half humans act on — it is more specific and sounds more confident. RR-2VFFCD's resolution claimed a "nearest-match suggestion" plus an "explicit none mention"; both were literally true and together produced a message that argued against itself.
severity: significant
resolution: |-
    `suggestIcon` now appends `NoIcon` to its candidate set before scanning. Suggestion cares about what is legal to WRITE, not what draws a glyph — `none` is legal, it just is not in the registry. `None` now suggests `none`, which is exactly right.

    The candidate list is re-sorted after appending so tie-breaking stays deterministic, which `TestSuggestIcon_IsDeterministic` pins.
status: addressed
