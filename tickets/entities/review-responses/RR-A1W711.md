title: '`rela channel ... -o json` writes bidi overrides and C1 controls from message content raw to the terminal'
finding: 'The table renderers pass every string through printable, but writeChannelJSON and the watch JSON Lines use encoding/json. That escapes only C0 controls, <>& and U+2028/9. U+202A-202E/2066-2069 (bidi) and U+0080-009F (C1, including U+009B CSI) from another author''s message props reach the terminal unescaped when a person runs `rela channel read/watch -o json` interactively. That allows Trojan-Source-style reordering of a displayed line, and on terminals that honor C1, escape sequences. Fix: post-process the encoded JSON to \u-escape Cc/Cf runes (the JSON stays valid and decodes to the same values), or document that -o json is for machine consumers only.'
severity: minor
resolution: -o json output (read, list, post, edit, remove, create and watch JSON Lines) goes through terminalSafeJSON, which writes every Cc, Cf, Zl and Zp rune as a \u escape (surrogate pairs above the BMP). The JSON decodes to the same values; test added.
