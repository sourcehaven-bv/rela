title: 'Write and delete bypass the collection''s where: filter'
finding: 'listTodos applies filter.MatchAll(cfg.Where); the write path applies nothing. Against where: [''status != done''] with a status=done entity, the reviewer reproduced: GET -> 404 (server says it does not exist), PUT -> 201 (title overwritten), DELETE -> 204. Not an ACL bypass - entitymanager still authorizes on the entity''s own type and the update-implies-read policy invariant holds - but a resource the server reports as 404 is nonetheless writable and deletable at that same URL, and the PUT plants an alias for an entity outside the collection. Read/write asymmetry on one URL space is how a presentation filter later gets mistaken for a security boundary. Related: entityIDFor returns alias.EntityID with no type check, while the derived-UID branch checks the type embedded in the CLIENT-SUPPLIED href rather than the stored entity''s actual type.'
severity: significant
resolution: |-
    PARTIALLY addressed. The type-confusion half is fixed: entityIDFor now validates the RESOLVED entity's actual type against the collection's entity_type, instead of trusting the type embedded in the client-supplied href (derived-UID branch) or checking nothing at all (alias branch). Verified DELETE still returns 204 for a real member and 404 for an unknown id.

    The where:-filter half is DEFERRED, deliberately. Applying the filter to writes is a behaviour change needing its own thought: a to-do the client legitimately holds can drift out of the filter between polls (that is exactly the completion case validateCalDAVCompletionReachable warns about), so 404-ing its write could wedge a client that has done nothing wrong - the same class of bug as the If-Match inversion in RR-6P8QL8. The reviewer also notes it is not an ACL bypass: entitymanager still authorizes on the entity's own type and the update-implies-read invariant holds. Needs a decision on whether where: is a presentation filter or a membership boundary, which is a design question for the ticket rather than a review fix.
reason: 'Deferred to a follow-up on TKT-MF1CWZ; not a regression and not an ACL bypass. The type-confusion half of the finding IS fixed on this branch.
