title: Claimed dead branch (requested == "") and the test covering it — premise incorrect
finding: Review reported that `requested == ""` in refuseWorldIncapablePath is unreachable from its only caller ("structurally impossible, not merely untested", verified by panic-instrumenting and running the suite), and that TestRefuseWorldIncapablePath_DefaultWorldPassesThrough therefore exists solely to cover a dead branch — recommending the test be deleted or the branch justified as defence-in-depth.
severity: significant
reason: |-
    The branch is live and load-bearing. `?world=` (explicit, empty value) makes `explicit` true, so the request passes attachWorld's `!explicit && configured == ""` early return and reaches the refusal with `requested == ""`. Verified empirically: `GET /api/v1/_analyze?world=` returns 200 (default world), and `req.URL.Query()["world"]` is `[]string{""}` with `.Get()` returning `""`. Without the empty check that request would 422 — breaking any client that appends an unset parameter. The reviewer's own reasoning visibly wavered mid-sentence here ("an empty `?world=` never gets here because ... actually reaching the refuse site with `requested == ""`"), and the panic instrumentation presumably missed it because no pre-existing test sends an explicit empty `?world=` on a refused route.

    The adjacent point was still valuable and was acted on: the ORIGINAL test was weak, because `?world=default` is already covered by TestAttachWorld_DefaultWorldIsUnaffected. Replaced it with TestRefuseWorldIncapablePath_EmptyWorldIsTheDefaultWorld, a router-level test covering the genuinely uncovered spelling (explicit-empty on two refused routes), with t.Run subtests. So the finding produced a better test via a false premise.
status: wont-fix
