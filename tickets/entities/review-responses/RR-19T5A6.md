title: normalizeSchemas accepts two types with the same plural
finding: 'internal/store/fsstore/layout.go:63. Normalizing empty plurals adds a new way to collide: type ''item'' with no plural becomes ''items'', and nothing rejects another type that declares plural ''items''. The metamodel does not check plural uniqueness either. Both types then write into one directory, and the reopen scan assigns every file to whichever type buildPluralToTypeMap kept, so the type changes silently. That is the same ''write lands where the scan reads it back differently'' defect this ticket fixes. Fix: reject duplicate plurals in normalizeSchemas (so both New and SetSchemas refuse them), and in SetSchemas also check new plurals against plurals of removed types still in paths.'
severity: minor
resolution: normalizeSchemas and the metamodel loader reject two types sharing a plural, compared case-insensitively.
status: addressed
