title: Transpiler cannot live in internal/filter (import cycle); build AST not source string
finding: 'Plan slice 2 puts the transpiler in internal/filter and checks only filter->predicate (leaf, fine). But the transpiler needs predicate host-fn NAMES for glob/regex/fuzzy/contains, which live in predicatefns (FuncMatch etc.), and predicatefns IMPORTS filter (predicatefns.go:31; arch-lint predicatefns->[predicate,filter]). So filter->predicatefns->filter is a CYCLE (compiler + arch-lint reject). FIX: transpiler goes in internal/predicatefns (already imports filter, owns the func-name constants AND EntityRecordType which supplies the typing) as predicatefns.FromFilter(...), NOT internal/filter/topredicate.go. Also (S3): build the predicate IR/AST directly rather than round-tripping a Lua source string — predicate.Compile runs values through gopher-lua''s parser, so a filter value containing '' or backslash or newline breaks out of the Lua string literal (injection/mis-parse; operator-controlled != escaping-safe). AST route avoids the quoting problem entirely.'
severity: critical
resolution: Transpiler lives in internal/predicatefns as FromFilter(meta, def, *filter.Filter) -> (source, error) — predicatefns already imports filter and owns the FuncMatch/etc. names, so no cycle. It emits predicate SOURCE (predicate exposes only Compile(env,source), no public AST builder), but every user value routes through luaStringLiteral which escapes quote/backslash/newline/control bytes as Lua escapes. TestFromFilter_ValueEscaping pins this incl. an injection attempt ('; return true; --) which compiles as a literal string comparison, not injected syntax. arch-lint unchanged (predicatefns already -> [predicate, filter, metamodel]).
status: addressed
