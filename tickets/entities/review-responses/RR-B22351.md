# Finding

A horizontally scrollable container that is not natively focusable, carries no
`tabindex`, and holds no focusable descendant cannot be reached with Tab, so a
keyboard-only user cannot scroll it and content past the right edge is
unreachable. Markdown cells frequently contain no links, so "it has a focusable
child" is not a defence. (axe `scrollable-region-focusable`; ACT rule 0ssw9k;
WCAG 2.1.1 Level A.)

Two aggravating facts:

1. The in-repo idiom the plan proposed to copy is itself non-conformant —
neither `.table-wrapper` (`EntityDetail.vue:2838-2840`) nor
`.table-scroll-wrapper` (`EntityList.vue:1707`) carries `tabindex`.
2. **The current `.md-body { overflow-x: auto }` already has this defect, but it
has never fired because of the very bug this ticket fixes.** Fixing the wrapping
bug therefore *activates* a previously dormant keyboard trap. That inverts the
assumed risk ordering: the "safe" part of the change is not safe on its own.

# Resolution

Fixed in the implementation. `wrapTablesForScroll`
(`frontend/src/utils/markdown.ts`) emits the scroll container with all three
attributes:

```html
<div class="md-table-scroll" role="region" tabindex="0" aria-label="Table: …">
```

The accessible name comes from the table's `<caption>` when present, else its
first three column headers (`tableLabel`), because an unnamed `role="region"` is
announced as a bare "region" and tells the user nothing.
`.md-table-scroll:focus-visible` carries the app's standard two-shadow focus
ring (`styles/markdown-content.css`), since a tab stop with no visible indicator
is its own defect.

Verified live: all four wrappers render `tabindex="0"`, `role="region"` and a
meaningful label (e.g. `Table: Competentie, Niveau, Verworven via, …`). Pinned
by `markdown.test.ts` and mutation-checked — deleting the
`setAttribute('tabindex', '0')` line fails the test rather than passing
silently.

**Deliberately not done**: the tab stop is unconditional rather than applied
only to tables that actually overflow, which would need a `ResizeObserver`
measuring layout at render time. A non-overflowing table therefore adds one dead
tab stop. Accepted as the simpler trade; recorded here so it is a decision, not
an oversight.

**Follow-up not in this ticket**: the two pre-existing app-table wrappers
(`.table-wrapper` in `EntityDetail.vue`, `.table-scroll-wrapper` in
`EntityList.vue`) have the same missing-`tabindex` defect. They are app layout
tables, out of scope for `.md-body`, and are left for a separate ticket.
