title: 'Q2 rationale is wrong: a full-round fallback frame on a busy board reveals nothing a plain list''s frame does not'
finding: Step 6 and alternative 7 drop the fallback frame for busy boards in full rounds too, because "a full round that a hidden write started would otherwise frame the board". In a full round, collect selects every non-syncing subscription unconditionally (live.go:838-871, only == nil). So whether a busy pair is in the round, and where the cap cuts it, does not depend on any channel change. Its fallback frame carries exactly the one bit "a full round overflowed" that every plain list already gets today (live.go:912-914), and the plan keeps that frame for plain lists in AC 8. The busy-specific oracle exists only in topic rounds, where selection depends on moves, including moves on channels the subscriber cannot read (AC 7). The hub does not need to know which change selected a pair. It only needs to know the round type, and replayRound already has it (only != nil, live.go:729-760). Exempting busy boards in full rounds costs liveness on the main kanban board under load, because a status-column change that overflows waits a rotation instead of refetching, and it buys no secrecy. Change step 6 to `if !s.inbox && !(s.busy != "" && topic)`, passing the round type into fallback. Change AC 8's "full round" subtest to expect the fallback frame. Rewrite alternative 7, Q2 and the Risks paragraph.
severity: significant
resolution: 'Adopted: fallback takes the round type and skips the frame for a busy board only in topic rounds, so full rounds keep the fallback frame (Approach step 8). AC 8 now expects the frame in a full round, and alternative 7, Q2 and Risks are rewritten.'
status: addressed
