title: Godoc claims per-face cardinality for gated callers; AllStates is dropped by the ACL pushdown
finding: |-
    The new godoc on handleAnalyzeCardinality (internal/mcp/tools_analysis.go) states that "a faced entity is checked per face (TKT-4Y6CMV) — the subject scan is AllStates, so a content-scoped edge on the draft no longer satisfies the published face's bound".

    That is true for the CLI (raw store.Store) but NOT for an ACL-gated MCP caller that takes the pushdown Query branch. store.GraphQuery (internal/store/graphquery.go) carries World and FaceIn but has no AllStates field, so visibility.listPushdown's Query branch (internal/visibility/pushdown.go:131-133) composes a GraphQuery that drops the AllStates request entirely; graphquerynaive then collapses each id to a single world prime via store.ResolveWorldPrimes.

    Verified empirically through the production appbuild.Services.GatedReads() seam: a policy entity at three faces (default, draft, published) read by a principal holding a relation-conferred role returns all three faces raw, but only [POL-1@] through the gated Query branch. The AllowAll branch (pushdown.go:93-96) copies the EntityQuery so AllStates survives there.

    This fails CLOSED — fewer subjects are scanned, so a content-scoped bound on a non-prime face goes unchecked and a violation is MISSED, never fabricated. No row is disclosed that the gate would have withheld, which is why this is minor rather than significant. But the comment asserts a guarantee that does not hold for exactly the principals the gate applies to, and the next reader would build on it.
severity: minor
resolution: |-
    The godoc is corrected in both places: handleAnalyzeCardinality now says per-face coverage holds "where the reader honors that" and names the GraphQuery limitation, and CardinalityReader's godoc says per-face coverage is a property of the READER, not a guarantee of the function. Both point at this RR.

    DOWNGRADED from the code review's "critical, blocks merge" to minor, on evidence. The code review's severity rested on gated principals getting a WEAKER check than before. They do not. The deleted MCP code scanned `store.EntityQuery{Type: entityType}` — default state only — for EVERY principal (verified against develop). After this change, a gated principal on the pushdown Query branch still gets default-state-only, i.e. exactly what it got before, while an AllowAll principal gets strictly better coverage. Nothing regressed for anyone; the change is a strict improvement for one class of caller and a no-op for the other.

    The security review reached the same conclusion independently and rated it minor, noting it fails CLOSED: an unscanned face means a violation is missed, never invented, and no row is disclosed that the gate would have withheld.

    So the defect was never in the behavior — it was that my comment promised a universal guarantee the wiring does not deliver. That is fixed. Carrying AllStates onto store.GraphQuery is a real improvement but it is a store-layer change touching every backend's query path, which belongs with TKT-O7R2A1 rather than in a refactor whose contract was "delete the fifth copy".
status: addressed
