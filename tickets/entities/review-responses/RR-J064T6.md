## Finding

The plan says applied-list names must be "validated as a safe path segment
before being matched against directory entries" but never states the rule. That
is the gap the design review exists to close — an unspecified validation
strategy is how blocklists get written by default.

Migration names are now **semi-trusted input**: they round-trip through
`migrations/applied.json`, a committed file an operator hand-edits and a merge
conflict resolves. They are then compared against, and potentially joined with,
real directory entries.

## Required

**Allowlist, not blocklist.** Specify the accepted form exactly:

```text
^[0-9]{14}-[a-z0-9]+(-[a-z0-9]+)*\.ya?ml$
```

Reject anything else outright — never sanitise and continue. Apply it on
**both** sides:

- when listing `migrations/` (so a hostile filename never enters the chain);
- when reading `applied.json` (so a hand-edited entry cannot name `../../etc/…`).

Validating only one side is the classic TOCTOU-adjacent mistake here: the
applied-list is compared against directory entries, so both populations must be
drawn from the same validated alphabet or the comparison is meaningless.

Note `file.go:300-308` currently filters only on `.yaml`/`.yml` suffix and
directory-ness. That was sufficient when names were never persisted anywhere; it
is not sufficient once they are.

## Also unspecified

- **Case sensitivity.** On macOS (case-insensitive by default) `0001-Foo.yaml`
and `0001-foo.yaml` are one file but two distinct applied-list entries — so a
migration could re-run, or appear applied when it is not. The allowlist above
forbids uppercase, which resolves it; if that is too strict, the comparison must
be explicitly case-folded and the reason recorded.
- **Unicode / NFC-NFD.** Same class of problem: two byte-sequences, one file.
The lowercase-ASCII allowlist forecloses it.
- **Duplicate timestamps.** Two files minted in the same second collide on the
numeric prefix but differ in slug, so they sort deterministically — but the plan
should say that explicitly rather than leaving it to be discovered.
- **Length.** A 255-byte filename limit is reachable with a long slug; cap it.

## Severity

Significant rather than critical: the trust boundary is the operator shell, so
this is not a remote-attacker path. But the applied-list is a NEW hand-editable
surface that did not exist before, and "operator-authored" does not mean
"well-formed" — a bad merge resolution is the realistic failure, not malice.
