title: Creator branch never uses channels_creator_idx
finding: 'internal/channels/sqlchannels/waiting.go:69 renders `created_by_user = ? AND type IN (...)`, but the index (internal/sqlitedb/sqlitedb.go channelCreatorDDL, pg 0034) is partial on `created_by_user <> ''''`. SQLite cannot prove that predicate from a bound parameter, so it never picks the index. Verified with EXPLAIN QUERY PLAN on the same schema: with channels_state_idx it searches by (tomb, state), which reads every open channel; without it, it does a full SCAN. Adding `created_by_user <> ''''` literally to the query switches the plan to `SEARCH channels USING INDEX channels_creator_idx (created_by_user=? AND type=?)`. Postgres has the same problem once pgx''s cached statement goes to a generic plan. So every inbox call and every watch replay scans all open channels on both database backends, and docs/realtime.md ("The database backends read the creator from an index") is false. Fix: add `created_by_user <> '''' AND` to the creator WHERE, and pin it with an explain test next to internal/channels/sqlitechannels/due_explain_test.go (TestListSessionsDue_UsesIndex).'
severity: significant
resolution: Creator queries carry the literal created_by_user <> '' and the index gained state; sqlite and postgres EXPLAIN tests pin index use
status: addressed
