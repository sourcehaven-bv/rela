**Finding (design review, TKT-WAV8XP PR-A planning).**

AC5 ("`analyze states` subtracts declared faces") is not implementable as
stated, because it treats the declared set as flat.

`faces:` is declared per entity type (`entities.<type>.faces`), so the
declared set is a map `type → set`. But `internal/analysis/states.go:104-169`
aggregates `byFace map[entity.Face]*ptrAgg` across every type and emits
one finding per face value with `Subject: string(p)`.

Failure case: `page` declares `draft`; `policy` declares nothing. A
`POLICY-1@draft` row exists (hand edit, or a schema change that dropped
`faces:` from `policy`). Flat subtraction marks `draft` declared, suppresses
the finding, and a genuinely stranded row becomes invisible. That is the class
that matters most under worlds: rule 1 says a faceless type contributes its
default state in every world, so `POLICY-1@draft` is content reachable through
no world whatsoever.

The information is already present — `stateRow.typ` at `states.go:46-49`.

**Resolution:** subtract per `(type, face)`. Either re-key `byFace` on the
pair and change `Subject` to the state-ref shape, or keep the face-keyed
headline finding and filter each row at `states.go:119` with `if
declared[st.typ][st.face] { continue }`. AC5 must say WHICH, because it
changes the JSON consumer contract (`Subject`). Add a negative test: *a pointer
declared on type A but stored on type B still reports.* Also decide in the plan
what happens for a `headless-family` row, where `st.typ` is the state's own type
and may match no declaration.
