type: review-response
title: IsReserved is not control-char safe, so its standalone-correctness claim is false
finding: 'IsReserved does TrimSpace + HasPrefix, which handles \t and spaces but NOT C0/DEL control characters. Verified: IsReserved("\x01system:scheduler") == false and IsReserved("\x7fsystem:scheduler") == false, while sanitizeUser turns both into exactly "system:scheduler". The end-to-end HTTP paths are safe today only because sanitizeUser runs BEFORE IsReserved sees the value -- safe by ordering, not by construction. Two concrete problems: (1) provision.go calls IsReserved on an unsanitized `sub`, and the test comment in principal_test.go explicitly claims IsReserved ''must be correct standalone'' for that reason -- a claim the function does not satisfy. (2) stampAuditPrincipal takes an arbitrary exported PrincipalResolver, so a future resolver returning an unsanitized User (cookie, query param, gRPC-gateway header) would hand IsReserved a raw value, get false, and nothing downstream re-checks. The whole stated design point of the prefix rule was ''safe by construction rather than depending on someone remembering''.'
severity: significant
resolution: 'Made IsReserved correct on a RAW value rather than only a pre-sanitized one. It now strips the LEADING run of ASCII whitespace and C0/DEL control codes (via a new trimReservedNoise helper) before the prefix test, so "\x01system:scheduler" and "\x7fsystem:scheduler" are reserved regardless of whether the caller sanitized first. Only the leading run is stripped: the prefix test anchors at position 0 so interior noise cannot manufacture a prefix, and stripping interior characters would conflate names the ACL treats as distinct (its assignment lookup is an exact map index). Pinned by 7 new table rows in TestIsReserved covering leading C0/DEL/NUL, mixed leading noise, and both interior cases. Also corrected the misleading test comment that asserted standalone correctness the function did not have -- it now explains the property and why safe-by-ordering was the wrong basis.'
status: addressed
