title: pointerDeclared used a raw map index where the codebase resolves aliases — false undeclared-pointer findings
finding: 'analysis/states.go pointerDeclared indexed s.deps.Meta.Entities[entityType] directly. metamodel.GetEntityDef exists precisely for this and resolves aliases and case; there are 96 non-test GetEntityDef call sites, and states.go was the ONLY raw Meta.Entities[...] index in internal/analysis, so this was a new inconsistency rather than a pre-existing one. The write path never canonicalizes e.Type (only importer.go does, on import), so a stored entity legitimately carries an alias as its type. Verified: with page{Aliases: [webpage], Pointers: {draft, published}} and a row typed ''webpage'' at pointer ''published'', pointerDeclared returned true for ''page'' and FALSE for ''webpage'' — a false undeclared-pointer finding an operator cannot act on, because the pointer IS declared. Severity is minor because the consequence is a noisy report rather than data loss. The reviewer noted a mirror-image concern in the compiler: compileWorld keys byType on canonical names only, so an alias-typed row would hit For(alias) => ok=false => rule 1 => default state served in world:published, which is genuinely fail-open in PR-D.'
severity: minor
resolution: 'Fixed in 322aa4b6. pointerDeclared now uses s.deps.Meta.GetEntityDef(entityType), with a comment recording why (the write path does not canonicalize e.Type, so a raw index reports every state of an alias-typed entity as stranded). Pinned by TestCheckStates_SubtractionResolvesAliases; mutation-tested — reverting to the raw map index fails with count = 1 on a declared pointer. The test calls meta.InitAliases(), since alias resolution runs off an unexported map that only Parse builds. For the compiler mirror: rather than teach the store about aliases (it holds no metamodel and structurally cannot resolve one), the contract is now WRITTEN on the WorldScope godoc under a ''# Type keys are CANONICAL'' heading — callers must canonicalize before calling For, and the doc names the failure as fail-open (alias => unknown type => ok=false => rule 1 => default state in a world that meant to exclude). That is the decision PR-D needs and it is recorded where PR-D will read it. Found by code review.'
status: addressed
