title: Watching read_session on a channel that is not stored yet returns "changed" immediately, so the watch never waits
finding: 'For a cardinality-one channel with no message, `sessionView` builds `channels.Channel{CreatedAt: now}`, and `currentSession` sets `EnteredAt: ch.CreatedAt` (`realtime/session.go:113-115,128-132`). Every replay uses a new `c.now`, so the read_session digest changes on every pass. The first waiting pass, or the 2s channel poll (`mcp/tools_watch.go:458-460`), reports a change. A session that has not started yet but waits for a person in its initial state is the main case for an agent wait. read_channel already has this problem, and live replays of an unstored head have it too. Change: for an unstored channel, leave `entered_at` out (nil or zero) of the session view, as `due_at` already is ("set only on a stored, open channel"). Otherwise make the read_session result deterministic another way. Add an unstored-channel row to `TestWatch_ReadSession` that asserts the watch times out with no change.'
severity: significant
resolution: An unstored channel's session view leaves entered_at out (omitzero), fixing read_channel and live replays; AC 23 asserts a read_session watch on it times out.
status: addressed
