title: Version-ordinal & record_id computed app-side post-commit → silent lost versions / lineage collision under multi-writer
finding: 'The plan writes version rows at the entitymanager boundary POST-COMMIT, best-effort (B1), but introduces three cross-row invariants the audit log never had: PRIMARY KEY(record_id, version), unique record_id, and the record_current mapping. These are enforced outside the store''s write tx, across multiple processes. Concretely: (F1) two processes editing the same entity both read max(version)=N, both INSERT version N+1; the PK makes one fail, and because B1 has no retry the losing version is SILENTLY DROPPED — the live entities row reflects the edit but history is missing a real committed state. (F2) record_id minted app-side (max+1) has no write-tx PK backstop (unlike entities.id, which is saved by INSERT ON CONFLICT inside the store tx per entity.go:222) — colliding mints drop history entirely or split one record into two. Root cause: the plan inherited the audit hook''s PLACEMENT but not its safety envelope; audit tolerates best-effort post-commit because it has zero cross-row invariants (audithook.go just appends). Evidence: manager.go:534 (post-commit hook), entity.go:254-279 (independent per-write tx), 0001_init.sql:21/31 (rela_seq sequence + entities PK), core.go:213-222 + entity/id.go:159-185 (the racy max+1 pattern NOT to copy).'
severity: critical
resolution: 'Resolved by redesign, not patch. Capture moved from per-write (post-commit, cross-process racy) to a periodic reconciliation SWEEP under a non-blocking pg_try_advisory_lock → version writes are effectively single-writer, so the ordinal race cannot occur. The app-minted record_id is eliminated: versions key on (entity_id, vseq) where vseq comes from a dedicated version_seq SEQUENCE (cross-process safe, gap-tolerant); the display ordinal is computed at read time. Lineage across rename is derived from op=rename version rows, not a maintained record_id. Delete is captured synchronously (the one on-write-path case). See PLAN-W9WD26 Approach + AC-9 (two-connection concurrent-sweep test).'
status: addressed
