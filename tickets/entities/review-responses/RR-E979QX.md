title: /api/open-file spawns an OS process on the same mux with no authorizer
finding: |-
    [security] `/api/open-file` (internal/dataentry/commands.go:719) is mounted by the same registerCommandRoutes as `/api/command/`, and spawns an OS opener (xdg-open/open/explorer) via cmd.Start() without consulting the commandAuthorizer at all. On a non-loopback bind with no acl.yaml — exactly the deployment TKT-AQIT9M closes for /api/command/ — this remains reachable unauthenticated.

    Impact is bounded and is NOT RCE like the fixed bug: argv array with `--` flag-stopping, containedProjectPath containment, the program name is a compile-time constant, and no output returns to the caller. What remains is unauthenticated remote process spawn plus a project-file existence oracle (404 vs 200 distinguishes present from absent).

    Pre-existing, not introduced by this ticket. Raised because TKT-AQIT9M establishes commandAuthorizer as the gate for this handler's process-launching surface and leaves a sibling on the same mux outside it — the drift the seam exists to prevent.
severity: significant
resolution: 'Deferred to TKT-PYPNWO, which already covers this exact surface: its title is ''Command file actions (open/reveal) launch xdg-open on the server — no-op and unsafe for remote deployments'', and its proposed fix already includes ''refuse /api/open-file when running as the HTTP daemon on a non-loopback bind''. Gating it here would widen TKT-AQIT9M beyond the command-exec decision seam it is scoped to, and would half-fix PYPNWO (the no-op-on-headless half would remain). Recorded here so the gap is traceable from this ticket rather than only from PYPNWO.'
reason: 'Deferred to TKT-PYPNWO rather than fixed here, for three reasons. (1) Ownership: TKT-PYPNWO already covers this exact surface — its title is ''Command file actions (open/reveal) launch xdg-open on the server — no-op and unsafe for remote deployments'', and its proposed fix already includes ''refuse /api/open-file when running as the HTTP daemon on a non-loopback bind''. The finding is not new information to the backlog. (2) Scope: TKT-AQIT9M is scoped to the command-exec decision seam — replacing a per-request ACL type-switch with a wiring-time authorizer. Gating a second, differently-shaped handler here widens the ticket past that seam and past what its planning checklist and acceptance criteria were reviewed against. (3) Completeness: gating /api/open-file here would only half-fix PYPNWO, leaving its other half (the opener silently no-ops on a headless server, so the UI reports success for something that never happened) open, and would make the remaining work harder to reason about because the surface would then be half-owned by two tickets. Severity is genuine but bounded: it is unauthenticated remote process spawn plus a file-existence oracle, NOT the RCE this ticket fixed — argv array with `--` flag-stopping, containedProjectPath containment, a compile-time-constant program name, and no command output returned to the caller. It is also strictly pre-existing: this ticket neither introduced it nor widened it.'
status: deferred
