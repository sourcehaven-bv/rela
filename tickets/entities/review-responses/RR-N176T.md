type: review-response
title: Regex host func ReDoS — RE2 guarantee is load-bearing
finding: 'Phase 1 adds glob/regex/fuzzy as predicate host functions. predicate''s eval step budget (10_000) bounds the number of IR steps but does NOT bound wall-clock time inside a single host-function call. A catastrophic-backtracking regex would therefore hang eval despite the budget. Mitigation is sound but must be explicit and verified: Go''s regexp is RE2 (non-backtracking, linear-time) so no catastrophic ReDoS is possible by construction, AND internal/filter already compiles glob/regex/fuzzy-wildcard through regexp.Compile (confirmed: filter.go:123/137/158, pattern.go:44). Reusing that path preserves the guarantee. Action: (1) route the new host funcs through the same regexp path, never a backtracking engine; (2) document in predicate/doc.go that RE2''s linear-time property — not the step budget — is what bounds host-func regex time, so this invariant is not silently lost in a future refactor.'
severity: significant
resolution: 'Host functions (match/regex/fuzzy/contains/today) live in a NEW package internal/predicatefns, NOT in predicate core (which mayDependOn: [] per arch-lint, and would form a cycle with the Phase-2 filter->predicate transpiler if it imported filter). predicatefns imports internal/filter and routes every string matcher through filter.ParsePattern (glob->RE2), stdlib regexp.Compile (regex, RE2), and filter.TrigramSimilarity (fuzzy) — never a backtracking engine. The RE2 linear-time guarantee (not the eval step budget, which doesn''t bound a single host call) is what prevents catastrophic ReDoS; this is documented explicitly in the predicatefns package doc so a future refactor can''t silently swap in a backtracking matcher. today() takes the ''now'' instant from the caller (not the wall clock) so eval stays pure. Verified by internal/predicatefns/predicatefns_test.go incl. positive+negative fuzzy. Arch-lint updated: predicatefns mayDependOn [predicate, filter].'
status: addressed
