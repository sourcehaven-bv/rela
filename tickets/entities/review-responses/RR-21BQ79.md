title: GC deletes seen shards while realtime is degraded or off
finding: §3 "GC" deletes the shards of every rule id that is in the index but not in the current rules. `rulesFor` returns nothing when the config is Degraded or nil, so a reconcile during a degraded spell, or while realtime.yaml is briefly missing, wipes the whole seen-set. On recovery, every rule then either baselines silently (everything that entered meanwhile is lost, which breaks AC9) or, if the shards are deleted but the index write fails, posts `enter` for every current match. Skip GC unless the config is present and not Degraded, and remove index entries before deleting their shards.
severity: critical
resolution: GC runs only when the config is present and not degraded. It removes index entries before it deletes their shards.
status: addressed
