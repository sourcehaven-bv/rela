title: AC6 (data-destruction guard) does not cover the automation/cascade update path
finding: 'AC6 pins that rela.update_entity preserves hidden properties, but as written it exercises a directly-constructed runtime. The realistic destruction path is an AUTOMATION: a user with a field policy triggers a write, a cascade script calls rela.update_entity on some other entity, and if that runtime''s write-prep read were ever redacted the hidden props are erased under an identity that isn''t even the script author''s. Add an end-to-end case through the cascade path (autocascade → LuaScriptRunner → update) asserting the store retains hidden properties. Also worth a static guard: an assertion/test that RawStore is the ONLY handle luaUpdateEntity touches, so a future refactor that ''tidies'' the two fields together fails loudly rather than silently destroying data.'
severity: significant
resolution: 'AC6 extended: the hidden-property-preservation test runs BOTH directly and end-to-end through the cascade path (autocascade → LuaScriptRunner → rela.update_entity), plus a guard test asserting luaUpdateEntity touches only WritePrepStore so a future ''tidy the two fields together'' refactor fails loudly instead of destroying data.'
status: addressed
