title: entitymanager routes rename through non-atomic decomposition instead of atomic store.RenameEntity
finding: 'The strongest architectural finding (reviewer #6, corroborated). store.Store declares RenameEntity with an atomic contract (''all relations referencing the old ID are updated atomically''), and ALL THREE backends implement it: fsstore/entity.go:367, memstore/memstore.go:419, pgstore/entity.go:358 (a single Begin/Commit transaction that also checks newID conflict inside the tx). It is covered by the storetest conformance suite. Yet entitymanager/rename.go:19 routes Manager.RenameEntity through rename.Rename — the store-agnostic decompose-into-create+delete path — not m.deps.Store.RenameEntity. That decomposition is the ROOT reason the lost-update (create side, this bug) and partial-failure/re-run problems exist at all. My PR (BUG-5QDV6F) hardens only the create half of a decomposition that arguably should not be on the rename write path. No documented reason for the decomposition was found; it looks like historical carryover from the workspace era (#143/#702) predating or paralleling the store method. Retiring the bug class fully = have entitymanager call st.RenameEntity (which every backend provides atomically), keeping rename.Rename only as a fallback for a hypothetical store that lacks it (none today). This is a larger, separate change touching audit/version capture and DryRun — a design decision, not a silent fold-in.'
severity: significant
resolution: 'Re-routed Manager.RenameEntity through the atomic store.RenameEntity on every backend and DELETED the internal/rename package entirely (single production caller; no store lacks RenameEntity since it is a mandatory store.Store interface method, so no fallback needed). entitymanager/rename.go is now a thin adapter: real writes call st.RenameEntity (translateRenameErr maps ErrNotFound->ErrEntityNotFound, ErrConflict->ErrEntityAlreadyExists); DryRun is planned read-only via planRename (validate newID, old exists, new free, count incident relations). Removed the internal/rename component + all its deps from .go-arch-lint.yml. This retires the whole lost-update/clobber/partial-failure class at the source rather than hardening one half of a decomposition. Verified: go build ./..., go test -race entitymanager+cli+mcp+store/... green (incl storetest + pgstore), arch-lint OK, golangci-lint 0 issues, coverage floors PASS.'
status: addressed
