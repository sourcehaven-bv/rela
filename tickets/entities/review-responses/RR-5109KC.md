title: 'MCP body cap premise wrong: SDK caps at 4 MiB'
finding: 'go-sdk defaults MaxRequestBodyBytes to 4 MiB, so an outer MaxBytesReader is dead code and uploads above ~3 MiB fail. Raising it globally invites memory exhaustion (~5 copies per upload). Fix: set MaxRequestBodyBytes via HTTPHandler option sized from a dedicated MCP upload cap min(max_attachment_bytes, 16 MiB); reject by DecodedLen before decoding; stream-decode base64 into CapAttachmentReader.'
severity: significant
resolution: Set StreamableHTTPOptions.MaxRequestBodyBytes to EncodedLen(16 MiB) + 1 MiB in Server.HTTPHandler; no outer MaxBytesReader. TestAttachments_HTTPAcceptsLargeUpload posts 5 MiB through the handler.
status: addressed
