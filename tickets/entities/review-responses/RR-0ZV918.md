title: 'SetSchemas indexes files silently: no search, no events, no mentions'
finding: 'internal/store/fsstore/schemas.go:68. Files that join the index on SetSchemas are not passed to notifyPut, not emitted to subscribers, and not given to noteMentions. GetEntity and ListEntities return them, but search_entities, the realtime/MCP watch subscribers and the mention index do not see them until restart. The common trigger is a git pull or branch switch that adds a type and its files together: startup backfill ran before the type existed, so nothing ever indexes them for search. The ''same as New'' justification does not hold, because New''s files are backfilled by appbuild and SetSchemas'' files never are. Fix: after publishing, load each found entity (loadEntityMeta) and do what reconcileEntityPath does (noteMentions, notifyPut, emit EventEntityCreated). It costs one body read per newly declared file, once per reload, under the locks already held. Add a test with a recording observer.'
severity: significant
resolution: 'Files that join the index on SetSchemas are loaded and announced like watcher-found files: mention index, notifyPut and EventEntityCreated; soft-deleted ids and id collisions are skipped with a warning.'
status: addressed
