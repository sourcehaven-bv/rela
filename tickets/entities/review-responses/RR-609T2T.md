title: 'Combined review: entity/list screenshot views hang 30s (only form has a readiness signal)'
finding: The renderability gate polls unconditionally for [data-testid^=form-state-], which only DynamicForm (the edit form) stamps. view="entity" → EntityView and view="list" → ListView render no such marker, so those captures poll until the 30s perCaptureTimeout and die with a misleading 'context deadline exceeded'. Both were documented as supported; every capture test used view=form, so CI stayed green while 2/3 of the documented view surface was broken.
severity: critical
resolution: Only view="form" is supported today; the resolver now rejects any other view LOUDLY ('view=X is not supported yet — only view="form"') instead of hanging. formURL simplified to the form route; entity/list dropped from the docs. Unit test TestScreenshot_UnsupportedView_FailsLoud. entity/list can be added later once those views expose an analogous terminal-state marker.
status: addressed
