title: Cache keys hardcoded the Go version, so reachability's floating '1.26' pin would miss forever
finding: 'Cache keys embedded the Go version as a copied literal. The reachability job pins go-version ''1.26'' (floating) while its key hardcoded the string ''1.26''. When 1.26.7 ships, setup-go installs it, the key does not change, and the job restores a build cache produced by 1.26.6. Go''s build cache embeds the compiler version in its content hash, so this is not a correctness bug — it is a permanent silent miss: the job pays full restore and save cost forever, hits nothing, and stays green because it is report-only. The same duplication between `go-version:` and the key is a drift bug on every toolchain bump.'
severity: significant
resolution: Gave every setup-go step an id and keyed all caches on ${{ steps.setup-go.outputs.go-version }}, the version actually resolved and installed. A patch release now rotates the key automatically and the literal appears once, in go-version:.
status: addressed
