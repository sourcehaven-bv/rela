title: Orientation *bool default-true is a nil-vs-false inversion trap
finding: ImageStep.Orientation is a *bool defaulting true; Config.Orientation is a plain bool defaulting false. Mapping omitted-YAML (nil→true) to Config (bool) is an easy place to invert the default and ship sideways images — exactly the regression this ticket exists to prevent (broken rotation worse than today).
severity: significant
resolution: 'Pin the default with a dedicated test: an image: step with NO orientation key, over a fixture tagged Orientation=6, MUST be stored upright. The nil→true mapping lives in one documented helper. Considered making orientation non-configurable in Phase 1 (always-on) to remove the trap entirely — flagged as the simpler option; leaning that way. Added AC + test.'
status: addressed
