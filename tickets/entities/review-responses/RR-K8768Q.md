title: Plural-change refusal wedges hot reload until restart, and only reaches stderr
finding: 'internal/store/fsstore/schemas.go:44 and internal/cli/mcp_wiring.go:180. A valid schema that changes a plural fails every later reload, not just this one: prev.paths keeps the old plural, so unrelated edits are refused too. The only signal is slog.Warn in watchSchema, which the MCP client never sees, and the advice ''reopen the store'' is internal jargon. Also, prev.paths includes types already removed, so dropping a type and later re-adding it with another plural is refused even when it has no index entries. Fix: only refuse when the type still has index entries (or files) in the old directory. Word the error for the operator, for example ''restart rela mcp to apply the new directory for type %q''. Consider sending it as an MCP log notification.'
severity: minor
resolution: A plural change is refused only while entities of the type exist, with a message saying to rename the directory and restart; SetSchemas applies every other change in the same reload; removed types leave paths.
