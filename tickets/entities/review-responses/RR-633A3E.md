title: Stdio identity limitation is acceptable but not cheap to fix in this slice
finding: Stdio and the CLI never run access.Opener, so principal.User stays the login there. Changing that means re-stamping the stdio principal at startup through acl.IdentityResolver, as access.Restamp does. That would also change authorship, read markers, pile owners and ownership checks for every CLI write, which is cross-cutting and beyond this slice. Accept the limitation, but document both directions. A person on stdio misses mentions of their user id. Replies to a message they posted over stdio target their login, so the web app never shows those replies. Open a follow-up ticket to resolve the stdio identity at startup when principal_property is set. Agents use job identities, which are the same key everywhere, so the demo is unaffected.
severity: minor
resolution: Limitation documented in both directions; follow-up b written to resolve stdio identity at startup when principal_property is set.
