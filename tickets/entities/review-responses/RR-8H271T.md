## Why these were worth fixing rather than noting

Three of the four are the same failure in different clothing: an assertion or a
comment that *reads* as evidence for a property while not actually testing it.
That is the exact shape this ticket's root cause has — a suppression-only test
that passed whether or not the fallback address existed — so leaving them would
have been inconsistent with the measure the bug adds.

The `set`-only negative is the clearest case: it would have kept passing if the
button had been rendered with a different class, which is the change most likely
to happen when someone implements `set:` later.
