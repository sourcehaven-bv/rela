The rel.<name>=<id> query-param prefill channel is independent of
link_relation/link_peer and registers no pickerTypes entry. The ownership filter
removed such keys before reshapeLegacyToModern saw them, so a create naming an
unrendered relation succeeded, wrote no edge, and reported nothing — converting
a loud abort into silent data loss.

Resolution: hoisted the prefilled keys to component scope (queryRelationKeys)
and exempted BOTH prefill channels via prefilledRelationKeys(), so an unowned
prefill is carried into the payload and an untypeable one fails loudly instead
of vanishing. The set is rebuilt from the query on each initializeDefaults run
rather than accumulated, so a template switch or add-another cannot leave a
stale exemption. Pinned by "never silently drops a rel.* prefill for an
unrendered relation", verified to fail against the unfixed code (the entity was
created with no error).
