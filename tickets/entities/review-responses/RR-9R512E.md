id: RR-9R512E
type: review-response
title: The injected checkbox had no accessible name
finding: The node view emitted a bare `<input type="checkbox" contenteditable="false">` with no aria-label and no associated label. A screen reader announced "checkbox, not checked" with no indication of WHICH task, which on a checklist of a dozen items is unusable. The item text sits in a sibling wrapper rather than a `<label>`, so there was no implicit association. Combined with the keyboard defect (RR-IZZROK), the whole affordance was inaccessible.
severity: significant
resolution: The checkbox takes its accessible name from the item's own text, set in the constructor from `node.textContent` (contentDOM is filled by ProseMirror after construction) and re-mirrored on every `update()` as the text is edited. A `<label>` would be the conventional association but fights contentDOM, which ProseMirror owns and rewrites. Pinned by a test asserting `aria-label` matches the item text.
status: addressed
