type: review-response
title: Cursor/Limit on the shared GraphQuery struct are silently ignored by three of four methods
finding: 'internal/store/graphquery.go:20-31. Cursor/Limit live on store.GraphQuery but are honored only by GraphQueryPage; GraphQuery, GraphCount, and MatchingIDs discard them without a word. The EntityQuery precedent makes this consistent, not good — it doubles the blast radius of a silent ACL failure mode: a caller sets Limit: 50, passes the query to MatchingIDs or GraphCount, gets unbounded results, and nothing signals it. Doc comments are the only defense and they do not fail builds. Reviewer proposes GraphPageQuery{GraphQuery; Cursor; Limit} so paging fields exist only where honored. Verified there is currently NO production caller of GraphQueryPage (only the conformance suite), so the split is free now and becomes a breaking change after the first consumer lands.'
severity: significant
resolution: 'Took the reviewer''s recommendation and split the type. Cursor/Limit were removed from store.GraphQuery and now live on a new store.GraphPageQuery{GraphQuery; Cursor; Limit}, which embeds the base struct so composition stays trivial (pageOf(q, n) helpers in tests; q.GraphQuery inside implementations). GraphQueryPage is the only method taking it, so the compiler now enforces that paging fields exist only where they are honored — setting a limit and calling GraphCount or MatchingIDs is no longer expressible. Verified before committing to the change that there is NO production caller of GraphQueryPage (only the conformance suite), so this cost nothing now and would have been a breaking change after the first consumer landed. Godoc on GraphPageQuery records the reasoning: GraphCount must count the whole matched set and MatchingIDs must answer for every candidate id, so neither CAN honor a limit — fields they silently ignored would be a quiet ACL footgun. This is a deliberate divergence from the EntityQuery precedent, which the reviewer correctly characterized as consistently bad rather than good.'
status: addressed
