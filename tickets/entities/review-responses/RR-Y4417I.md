title: RecordSuccess must clear the retry ladder atomically, or success pins a task to the ladder forever
finding: 'The plan specified RecordSuccess as `UPDATE ... WHERE last_run < $new`, which writes one column. But today''s recordSuccess (scheduler.go:449-460) does three things: sets Tasks[name], and deletes BOTH Failures[name] and NextRetry[name], with the comment ''Success clears the ladder. This is the ONLY reset''. If the store update omits the clear, a successful run leaves NextRetry set — and runDueTasks'' retry branch SUPPRESSES the normal schedule while a retry is pending, so the task fires only on ladder steps forever after. That is BUG-ZKK2UL re-opened from the opposite direction. Verified against the source: the clear is not incidental, it is load-bearing and documented as the only reset path.'
severity: critical
resolution: RecordSuccess is now specified as setting last_run AND clearing failures/next_retry in one atomic write, not a single-column update. Acceptance criterion 2 pins it with a conformance case, chosen deliberately because getting it wrong re-opens BUG-ZKK2UL rather than failing visibly.
status: addressed
