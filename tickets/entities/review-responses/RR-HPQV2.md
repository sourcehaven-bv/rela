id: RR-HPQV2
type: review-response
title: Value-length cap does not actually prevent ReDoS (backtracking blows up far below the cap)
finding: 'Empirically confirmed: the 10k value cap does not close the ReDoS hole. `(a+)+$` against a 41-char non-matching value (''a''*40 + ''!'') hangs indefinitely (>60s) — 240x below the cap. A quadratic pattern (a*a*$) is polynomial in input and takes seconds at a few thousand chars, still under 10k. The whole premise ''reject over-cap values so the match returns quickly'' is false: hang-time does not correlate with hitting the cap; a short pattern + short-to-medium non-matching value is the real attack and sails under both caps. The cap only bounds LINEAR-time regex work, which was never the threat. On the dynamic `form.v =~ form.pat` path this ticket explicitly targets, an attacker supplies a 6-char pattern + ~40-char value and wedges the render thread.'
severity: critical
resolution: 'Approach reworked entirely; the finding was correct and the cap-as-fix premise was abandoned. Threat model clarified with the user and now documented in the module doc: the `=~` PATTERN is operator-authored data-entry.yaml config (TRUSTED); the VALUE is user input via bindings (UNTRUSTED). The only genuine vulnerability was therefore a DYNAMIC pattern (`form.v =~ form.pat`) where a user supplies the regex — no length cap can make that safe. Fix: the parser now REJECTS any non-literal `=~` pattern at parse time (throws ConditionError), removing the untrusted-pattern path rather than mitigating it. The value cap is kept but explicitly relabelled as hygiene (bounding linear scan work, e.g. a pasted megabyte), NOT a ReDoS boundary. Re-review independently probed 6 bypass attempts (paren-wrapped ref, reversed operands, `not`, call, non-string literals) — all rejected at parse; confirmed no grammar path mints a `lit` from data. Accepted residual risk (operator writing a pathological literal into their own YAML, measured ~10s at 27 chars) is documented in-code as a foot-gun, not a vulnerability, with RE2/Worker named as the upgrade path if `=~` ever needs a data-sourced pattern.'
status: addressed
