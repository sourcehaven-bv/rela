## Finding

The plan describes `visibility.Redact` as "the single choke point every **Lua**
read path passes through" and lists only `internal/lua` among the consumers.
That is incomplete. `Redact` is also called directly from three data-entry HTTP
paths:

- `internal/dataentry/views.go:65` — `result.Entry`
- `internal/dataentry/export.go:311` — neighbor title derivation
- `internal/dataentry/export_list.go:447` — list-export title derivation

Populating a new field inside `Redact` therefore changes entities on the HTTP
surface as well, not just the script surface. The plan's scope section, its
"Files to modify" list, and its test plan all omit this.

## Verification performed

I traced whether the new field can actually leak onto the wire:

- `entitySerializer.toV1` (`entityserializer.go:45`) builds `v1.Entity`
field-by-field; it does not copy the struct. No implicit leak.
- `viewResult.Entry` reaches the wire via `serializer.forWire`
(`views_handler.go:544`), i.e. the same explicit builder.
- MCP uses its own DTO (`internal/mcp/convert.go:69`).
- No direct `json.Marshal` of an `entity.Entity` exists in the tree.
- `canonical.HashEntity` takes `entity.Entity` **by value** and hashes
only id/type/properties/body, so a new field cannot perturb the content hash.

So the leak risk is real-but-unrealized: today every wire shape is an explicit
DTO. The finding is that the plan did not establish this — it asserted a
Lua-only blast radius that the code does not support.

## Required plan changes

1. Correct the scope: `Redact` is a shared read-out choke point, not a
Lua one. The Lua exposure is the new part; the population is global.
2. Add a test asserting the marker does NOT appear in the v1 wire
output, so the "explicit DTO" property that makes this safe becomes pinned
rather than incidental. Without it, a future author adding a struct-copying
serializer silently changes the HTTP contract.
3. Keep `canonical.HashEntity` in the test plan, but note the by-value
signature already makes it safe — the test guards the invariant, it is not
fixing a defect.
