type: review-response
title: fs Purge crash windows lose the face purge record and leak filings
finding: filechannels/retention.go:260-285 moves the batch to trash before appending the purge record. If the append fails for a face batch, a retry returns ErrNotFound and the record is never written. A retry of a whole-entity purge appends a duplicate. Filing files left by a crash (ops.go writes the filing before the move) are never collected.
severity: minor
resolution: fs Purge now writes in a crash-safe order with deduplicated records and collects leaked filings (TestPurgeRetryWritesRecordsOnce, TestPurgeRetryAfterTrash, TestLeakedFilingIsCollected).
status: addressed
