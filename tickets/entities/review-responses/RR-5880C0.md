title: Delta cursor advances only over emitted events (tombstone gap)
finding: 'feed_provider.go:130 advances the since-cursor only over emitted events; an entity whose update dropped it from the filter (status→done) doesn''t advance the watermark and won''t re-emit under a delta poll, leaving a delta consumer with a stale event. The live ICS/JSON path is immune (always List with empty Since). Only bites a future delta/CalDAV client, where deletions are rela''s job anyway. Fix: document on List that delta callers handle tombstones separately (ICS has no delete semantics).'
severity: minor
resolution: 'Documented on List: the cursor advances only over emitted events, so a delta consumer must derive tombstones by diffing against the last-served ETag set. The live ICS/JSON path is unaffected (always full enumeration; ICS has no delete semantics). This is a note for a future delta/CalDAV client, where deletions are rela''s responsibility anyway.'
