## Why this belongs to BUG-G2BASF

The defect predates this ticket. The exposure did not.

`EntityDetail.vue` suppressed every command whenever a non-bare face was served,
so a faced address never reached `handleCommandExec` from the web app. This
ticket deletes that suppression and starts sending the served address. That is
the change that turns a latent hole into a reachable one, so the gate lands with
it rather than after.

## What the reviewer got right that I had missed

My own justification for deleting the gate cited `viewworld.go:150`
(`entry.Explicit`) and `commands.go` `ParseStateRef` as evidence that "both
contexts resolve the address correctly". Both claims are true, and both are
about **resolution**, not **authorization**. The view branch happens to be gated
as well; the entity branch is not, and I checked only the half that supported
the change.

The relevant asymmetry was documented one screen above the code I edited —
`buildViewInput`'s comment states the view payload is row-gated and
field-redacted — and I read past it.

## Scope

Fixed here rather than deferred: shipping the SPA half without the gate would
make a draft body reachable by an operator shell script in the same release.
