title: 'Nested-project claim is wrong: .rela marker preempts the parent-directory fallback'
finding: 'The plan''s edge-case section asserts ''Nested projects: child has metamodel.yaml, parent has schema.yaml -> child wins (nearest root). Guaranteed by checking both names per directory level.'' That is correct for the two filenames but ignores the third marker already in the loop. internal/project/context.go:62-66 checks for a .rela/ directory at EACH level, after the file check but before ascending. .rela/ is gitignored scratch state (scheduler-state.json, user-defaults.yaml, audit/) and can exist in a subdirectory that is not itself a project. Today that is mostly harmless because the file check and the .rela check agree at the real root. Under the new scheme the interaction matters more: a directory holding a stray .rela/ but neither schema file will be returned as the project root with SchemaPath pointing at a non-existent schema.yaml, and the walk stops before ever reaching the parent that has the real file. The plan''s AC-4 actually codifies this as intended behaviour without noting that it PREEMPTS finding a valid parent project. Decide and document explicitly: either the .rela branch should only match when a schema file is also absent all the way up, or AC-4 should state that a stray .rela/ shadows a parent project (status quo) and that the resulting error tells the user which directory was picked and why.'
severity: significant
resolution: 'Plan updated. Chose to preserve the .rela/ marker''s current precedence rather than alter discovery semantics as part of a rename ticket — changing it would be scope creep with its own regression risk. Instead the behaviour is now documented rather than silently assumed: AC-4 states that a directory with a stray .rela/ and no schema file IS selected as the root (stopping the walk before a real parent project is found) and requires the resulting error to name the selected directory so the situation is diagnosable. Added as an explicit edge case with a test, and listed under out-of-scope so the decision is traceable.'
status: addressed
