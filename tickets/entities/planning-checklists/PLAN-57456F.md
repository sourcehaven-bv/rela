## Plan

## Problem

A sync connector needs a 3-way merge base: the entity as it was at the last
sync. Recording a version number inside the entity changes the entity, which
makes a new version, so the number is always one behind. A tag that lives next
to the versions avoids that, and is useful on its own ("the version we sent to
X").

## Scope

In:
- `version_tags` table on pgstore (migration 0020) and sqlitestore (rung 13).
- A store capability `VersionTagger`, held to one contract by a storetest suite.
- `VersionMeta.Tags`, filled by `ListVersions`.
- An entitymanager method that authorizes, captures, tags and audits.
- Lua: `rela.tag_version`, `rela.untag_version`, `rela.version_by_tag`, and
`tags` on `rela.history` rows.
- CLI: `rela history-tag` (set/move/delete), tags in `rela history`.
- Purge refuses a tagged version unless `--force-tags`.
- Docs.

Out: tags on relation versions; the history panel UI; tags on fs/memory (no
versions there).

## Design

### Identity

A tag row is `(vseq, face, name, tagged_by_user, tagged_by_tool, tagged_at)`.
`vseq` is globally unique (pg `version_seq`; sqlite AUTOINCREMENT, never
reused), so the tag points at one version row. A tag is looked up through the
existing lineage walk: the tags of `(id, face)` are the tag rows whose vseq is
in that lineage. So a tag follows a rename without being rewritten, and a
recreated id does not inherit tags from the old lineage (the `[lo,hi)` fence
excludes them).

A name is unique per lineage and face. Moving a tag deletes the row with that
name among the lineage's vseqs and inserts the new one, inside the same lock or
transaction.

`VersionMeta` gains `Tags []string`. Ordinals renumber on purge; vseq does not,
which is why the tag holds vseq.

### Name grammar

`[a-z0-9][a-z0-9._-]{0,62}`, optionally prefixed by one namespace segment of the
same shape and `/`: `sent-to-board`, `sync/basecamp`. Validated in one place
(store package type `VersionTagName` with a parsing constructor), and refused,
not escaped.

### Capture now

Tagging without a version number tags the current state. If the newest version
in the lineage does not hold the live row's content hash, the store captures the
live row first, with the same op rule as the sweep (`update` when a lineage is
live, else `create`) and the live row's `last_edited_by_*` attribution
(`store.SweptPrincipal`), because the tagger did not write that content. The tag
row records the tagger. The sweep then finds the hash already captured and skips
it.

On pg this runs on one acquired connection under `sweepAdvisoryLockKey`, like
purge, so it cannot race a sweep tick. On sqlite it runs in one write
transaction.

### Store capability

```go
type VersionTagger interface {
    TagVersion(ctx, ref entity.Ref, name VersionTagName, version int) (VersionMeta, error) // version 0: current state
    UntagVersion(ctx, ref entity.Ref, name VersionTagName) error                             // ErrNotFound when absent
    VersionByTag(ctx, ref entity.Ref, name VersionTagName) (int, error)                      // ErrNotFound when absent
}
```

Separate optional capability, type-asserted like `HistoryReader`. Attribution of
the tag row from ctx (`principal.From`), never a parameter.

### Authorization (entitymanager)

`Manager.TagVersion` / `UntagVersion`:
- The ref is resolved like any write (bare id through `WriteTarget`).
- Default namespace: requires `update` on the entity (`authorizeAndAudit`
with `OpUpdate`). A tag is a write about the entity.
- Namespaced tag `ns/...`: also requires the per-entity permission
`tag:<ns>` (`HoldsPermissionForEntity`, like comment permissions). So an
operator grants `tag:sync` to the connector's `run_as` role, and a user who can
edit the ticket cannot move its sync base.
- No `acl.yaml`: allowed, like every other write.
- Audit: new ops `version-tag` / `version-untag`, subject entity, summary
`name=... version=...`.

Reading tags (`VersionByTag`, `Tags`) goes through the history visibility
wrapper, so a tag of a hidden entity reads as absent.

The `rela acl audit` dead-permission check learns that `tag:<ns>` is consumed.

### Purge

`PurgeRequest.ForceTags`. Purge computes the tagged targets before the dry-run
return, so the preview names them. It refuses unless forced; forced, it deletes
those tag rows in the same lock/transaction. Audit summary adds `tags_dropped=`.
CLI flag `--force-tags`.

### Lua

- `rela.tag_version(addr, name [, version])` → version number. Errors on a
bad name, a denied write, or a backend without versioning.
- `rela.untag_version(addr, name)` → true, or false when absent.
- `rela.version_by_tag(addr, name)` → the same table as `rela.get_version`,
or nil when the tag is absent or its version is hidden or purged.
- `rela.history` rows gain `tags` (a list of names).

Writes reach the manager through a new narrow `lua.VersionTagger` field on
`WriteDeps`; reads through the existing history reader interface, extended by
one method.

### CLI

`rela history-tag <addr> <name> [--version N] [--delete]`, operator shell like
other CLI writes but through the entitymanager (so it is authorized and audited
as the CLI principal). `rela history` prints tags beside each version.

## Acceptance criteria

1. Tagging the current state on pg and sqlite captures a version when the
sweep has not, and a following sweep does not capture it again.
2. Tagging an explicit version, moving a tag, and deleting a tag work;
`ListVersions` shows tags.
3. A tag follows a rename; a recreated id does not inherit tags.
4. Tags are per face.
5. Default namespace needs update; `ns/` also needs `tag:<ns>`. Denials are
audited; tag moves are audited.
6. Purge refuses a tagged version without `--force-tags` and drops the tag
with it.
7. Lua and CLI surfaces as above; fs/memory raise the "no versioning" error.
8. A bad name is refused.

it as dead.

## Design review revisions (binding; they override the sections above)

R1 (critical) Compare-and-set. Split the store API: `TagCurrent(ctx,
TagRequest{Ref, Name, Expect store.EntityVersion, PrincipalUser,
PrincipalTool})` and `TagVersion(ctx, TagRequest{..., Version int})`. Under the
lock, TagCurrent refuses with `store.ErrConflict` when `Expect` is set and
`store.VersionOf(live)` differs. Lua: `rela.tag_version(addr, name, {expect =
token})` or `{version = n}`; add `rela.version_token(addr)` returning the CAS
token of the current row through the gated reader (same token a redacted read
must yield; mirror whatever the data-entry API does for its ETag), and return
the token from `rela.update_entity` if cheap. A connector reads the token after
its own write and tags with it, so an edit in between is not absorbed.

R2 (critical) Lifecycle fence. Tags of (id, face) are the tag rows whose vseq is
in the lineage AND greater than the newest `delete` row of that lineage and
face. Moving a tag deletes any same-name rows in the whole lineage (all
lifecycles), so at most one exists. `VersionByTag` returns the newest vseq if
several ever exist. Tests: delete then recreate does not inherit; rename onto a
previously deleted id does not inherit.

R3 Attribution. The store never reads `principal.From`. `TagRequest` and the
untag request carry `PrincipalUser`/`PrincipalTool`, filled at the entitymanager
boundary; a zero principal is refused, not translated.

R4 Projection. Capture-now needs the schema hash/projection. Inject the
`ProjectionProvider` into both version stores at wiring; refuse if absent.
Extract the sweep's `captureOne` body into a shared function used by both.

R5 Lock. pg: blocking `pg_advisory_lock(sweepAdvisoryLockKey)` on one acquired
connection, bounded by `SET lock_timeout` / ctx deadline; tag, untag and purge
serialize on it. sqlite: one write transaction. Concurrent-move tests on both
backends.

R6 Inside a Tx. The store refuses `TagCurrent`/`TagVersion`/`Untag` when ctx is
inside `store.Tx` (pg: separate connection would see pre-write state; sqlite:
second writer deadlock). Test it. Synchronous automation Lua runs inside the
cascade; document that tagging belongs in background actions or scheduled
scripts.

R7 Content-free targets. Refuse tagging a `delete` or `purge` row. TagCurrent
when the newest row is a purge tombstone whose hash equals the live hash: error
("current state was purged"), never recapture.

R8 Bypass. One `authorizeTag` helper: an elevated (`allow_acl_bypass`) manager
skips both the update check and the namespace permission, as it skips every
check; documented. Non-elevated: `OpUpdate` via `authorizeAndAudit`, then
`tag:<ns>` via `HoldsPermissionForEntity`; a namespace denial is audited as
`denied-write` with a synthesized decision. Test both paths.

R9 `TagVersion` resolves the ordinal to a vseq under the same lock purge takes,
so a purge cannot renumber it mid-call. A caller whose ordinal came from an
earlier `ListVersions` may still name a shifted row; documented.

R10 DB backstop: FK `version_tags.vseq → entity_versions(vseq)` ON DELETE
RESTRICT (pg needs a unique index on `entity_versions(vseq)`; sqlite vseq is the
PK, foreign_keys pragma checked).

R11 Read gating: tag/untag/by_tag on a hidden entity fail exactly like a missing
one. `version_by_tag` goes through the same `addressAny` + historical redaction
as `get_version`. Note for TKT-SM20FG: a restricted `run_as` gets a redacted
base.

R12 Field write grants: tagging is `OpUpdate` with no fields; a principal with a
row-level update grant may tag even if its field grants are partial. Pinned by a
test.

R13 Grammar: at most one `/`. R14 Effort: l (ticket updated).

Additional ACs: CAS refusal (R1); no inheritance across delete/recreate or
rename-onto-deleted (R2); content-free target refused (R7); in-Tx refused (R6);
capture-now copies origin_* and last_edited_by_* like the sweep.
